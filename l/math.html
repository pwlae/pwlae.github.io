Math tricks

Read first: Counting things

Some problems are about numbers themselves: their digits, their remainders, their sums. A few small tricks turn them from puzzles into a few lines of code.

The idea

Think of a car's mileage counter. The right-most wheel shows the last digit. In Python you get it with n % 10: the remainder after dividing by 10. To throw that digit away, use n // 10: divide by 10 and drop the part after the point.

Do both again and again until the number is 0, and you visit every digit, from the right:

Modulo means wrap around. % is called modulo. Think of a clock: 3 hours after 11 o'clock is 2 o'clock, not 14. That is (11 + 3) % 12 == 2. The answer always stays between 0 and 11. Two handy uses:

  • n % 2 == 0: n is even.
  • n % 3 == 0: n divides by 3 with nothing left over.

Spot a loop with a set. Some problems repeat a step on a number: "replace n by the sum of the squares of its digits". Either you reach the goal, or you come back to a number you have seen before. Then you are stuck in a cycle (a loop that never ends). Keep every number you see in a set (see Hash maps and sets). If a number shows up twice, stop.

The set costs memory. The fast and slow pointers trick from Linked lists finds the same loop with O(1) memory: one number takes one step at a time, the other takes two, and if there is a loop they meet.

Look for a formula first. Before you write a loop, ask if maths already has the answer. The sum 1 + 2 + … + n is n * (n + 1) // 2. For n = 4: 4 × 5 / 2 = 10, and indeed 1 + 2 + 3 + 4 = 10. One line instead of a loop.

In Python

def digits(n):
    # digits of n, right to left
    out = []
    while n > 0:
        # last digit
        out.append(n % 10)
        # drop it
        n //= 10
    return out

def has_loop(n, step):
    # repeat step until we see
    # a number again (or reach 1)
    seen = set()
    while n != 1 and n not in seen:
        seen.add(n)
        n = step(n)
    return n != 1

def sum_to(n):
    # 1 + 2 + ... + n
    return n * (n + 1) // 2

digits(472)    # [2, 7, 4]
(11 + 3) % 12  # 2
sum_to(4)      # 10

Cost: a number n has about log10(n) digits, so digits is O(log n), which is tiny: even a billion has only 10 digits. sum_to is O(1): one sum, no loop.

Worked example

Is 19 "happy"? Square each digit and add, until you reach 1 or a repeat.

ndigitssum of squaresseen
191, 91 + 81 = 82{19}
828, 264 + 4 = 68{19, 82}
686, 836 + 64 = 100{…, 68}
1001, 0, 01 + 0 + 0 = 1{…, 100}

We hit 1, so 19 is happy. For 4 we would come back to 4 and stop: not happy.

LeetCode412. Fizz Buzz
Easy ~5 min☐ solved · https://leetcode.com/problems/fizz-buzz/
Hint
Use i % 3 == 0 and i % 5 == 0. Check "divides by both" first, or it never gets a turn.
Solution
class Solution:
    def fizzBuzz(
        self, n: int
    ) -> List[str]:
        ans = []
        for i in range(1, n + 1):
            # 15 = both 3 and 5
            if i % 15 == 0:
                ans.append("FizzBuzz")
            elif i % 3 == 0:
                ans.append("Fizz")
            elif i % 5 == 0:
                ans.append("Buzz")
            else:
                ans.append(str(i))
        return ans
# O(n) time.
LeetCode1281. Subtract the Product and Sum of Digits of an Integer
Easy ~5 min☐ solved · https://leetcode.com/problems/subtract-the-product-and-sum-of-digits-of-an-integer/
Hint
Take the digits out with % 10 and // 10. Keep a running product (start at 1) and a running sum (start at 0).
Solution
class Solution:
    def subtractProductAndSum(
        self, n: int
    ) -> int:
        prod, total = 1, 0
        while n > 0:
            d = n % 10
            prod *= d
            total += d
            n //= 10
        return prod - total
# O(number of digits).
LeetCode258. Add Digits
Easy ~10 min☐ solved · https://leetcode.com/problems/add-digits/
Hint
First solve it with a loop: add up the digits until one digit is left. Then the stretch: write out the answers for 1 to 20. Do you see them repeat every 9?
Solution
class Solution:
    def addDigits(
        self, num: int
    ) -> int:
        if num == 0:
            return 0
        # answers go 1..9, then
        # 1..9 again: wrap around 9
        return 1 + (num - 1) % 9
# O(1). This is the "digital
# root". The loop version
# is also fine.
LeetCode441. Arranging Coins
Easy ~10 min☐ solved · https://leetcode.com/problems/arranging-coins/
Hint
k full rows use 1 + 2 + … + k = k * (k + 1) // 2 coins. Find the biggest k where that is not more than n. A simple loop that adds rows works.
Solution
class Solution:
    def arrangeCoins(
        self, n: int
    ) -> int:
        k = 0
        # row k + 1 needs k + 1 coins
        while n >= k + 1:
            k += 1
            n -= k
        return k
# O(sqrt n) rows. With the
# formula and a square root
# it is O(1):
# (math.isqrt(8*n + 1) - 1) // 2
LeetCode202. Happy Number
Easy ~15 min☐ solved · https://leetcode.com/problems/happy-number/
Hint
Write a helper that turns n into the sum of the squares of its digits. Repeat it, and keep a set of numbers you have seen. A repeat means a loop: return False.
Solution
class Solution:
    def isHappy(self, n: int) -> bool:
        def step(x):
            total = 0
            while x > 0:
                d = x % 10
                total += d * d
                x //= 10
            return total

        seen = set()
        while n != 1:
            if n in seen:
                # a loop: never 1
                return False
            seen.add(n)
            n = step(n)
        return True
# Numbers shrink fast, so this
# is quick. Fast/slow pointers
# would need no set.
Interesting fact: The digit check on your bank card

The last digit of a credit or debit card number is a check digit. It is chosen so that a small digit sum, the Luhn algorithm, comes out right. Shops and websites run it before sending the number anywhere, so a typo is caught at once.

How it works: from the right, double every second digit. If a doubled digit is over 9, take 9 away. Add up all the digits. The number is valid if the total ends in 0, that is total % 10 == 0.

It catches every single mistyped digit, and almost every swap of two neighbouring digits (only 09 ↔ 90 slips through). It is named after Hans Peter Luhn of IBM, who filed the patent "Computer for verifying numbers" in 1954 (US patent 2,950,048). Today it is part of the ISO/IEC 7812 standard for card numbers.

Remember

  • n % 10 is the last digit, n // 10 drops it. Loop until 0.
  • % wraps around like a clock. A set (or fast/slow pointers) spots a loop.
  • Look for a formula first: 1 + … + n = n * (n + 1) // 2.
