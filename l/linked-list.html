Linked lists

Read first: Two pointers

A linked list is a chain of small boxes, where each box knows only where the next one is. Most linked-list problems are about walking that chain carefully and re-pointing arrows without losing anything.

The idea

Think of a treasure hunt. Each note has a clue (the value) and says where the next note is hidden. To reach note 5 you can't jump there. You have to follow notes 1, 2, 3, 4. The last note says "the end".

Each box is called a node. It holds a val and a next arrow pointing to the following node. The last node's next is None. The first node is the head, and you're usually given just that.

In Python

LeetCode gives you this class (it's shown in a comment above your code):

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

# walking the whole list: O(n)
node = head
while node:              # stops after the last node (node becomes None)
    print(node.val)
    node = node.next

Compared with a Python list: adding or removing a node once you're standing next to it is O(1), just re-point arrows. But finding the 5th node is O(n), because you have to walk there.

Three tricks

1. Dummy head. When building a new list, start with a fake node, so you never need a special case for "the list is still empty". Return dummy.next at the end.

dummy = ListNode()
tail = dummy
for v in [4, 5, 6]:
    tail.next = ListNode(v)   # attach a new node
    tail = tail.next          # move to the new end
return dummy.next             # skip the fake node

2. Fast and slow pointers. From the two-pointers lesson: slow moves 1 step, fast moves 2. When fast hits the end, slow is in the middle. And if the list loops back on itself, fast will eventually lap slow, like a faster runner on a track. That's how you detect a cycle.

3. Save before you re-point. Changing node.next throws away the old arrow. If you still need the rest of the list, save it in a variable first.

Worked example: reverse a list

Turn 1 → 2 → 3 into 3 → 2 → 1. Walk the list, flipping each arrow to point backwards. Three variables: prev (the already-reversed part), cur (the node we're flipping), and nxt (trick 3: the rest, saved before we flip).

prev, cur = None, head
while cur:
    nxt = cur.next      # save the rest
    cur.next = prev     # flip the arrow
    prev = cur          # step forward
    cur = nxt
return prev             # the old last node is the new head

LeetCode876. Middle of the Linked List
Easy ~10 min☐ solved · https://leetcode.com/problems/middle-of-the-linked-list/
Hint
Fast and slow pointers. Move slow one step and fast two steps while fast and fast.next exist. Return slow.
Solution
class Solution:
    def middleNode(self, head: Optional[ListNode]) -> Optional[ListNode]:
        slow = fast = head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
        return slow
LeetCode83. Remove Duplicates from Sorted List
Easy ~10 min☐ solved · https://leetcode.com/problems/remove-duplicates-from-sorted-list/
Hint
Duplicates sit next to each other. While the next node has the same value as the current one, skip it: node.next = node.next.next. Only move forward when they differ.
Solution
class Solution:
    def deleteDuplicates(self, head: Optional[ListNode]) -> Optional[ListNode]:
        node = head
        while node and node.next:
            if node.next.val == node.val:
                node.next = node.next.next   # skip the duplicate
            else:
                node = node.next
        return head
LeetCode206. Reverse Linked List
Easy ~10 min☐ solved · https://leetcode.com/problems/reverse-linked-list/
Hint
The worked example. Write the four lines inside the loop from memory: save, flip, step, step.
Solution
class Solution:
    def reverseList(self, head: Optional[ListNode]) -> Optional[ListNode]:
        prev, cur = None, head
        while cur:
            nxt = cur.next
            cur.next = prev
            prev = cur
            cur = nxt
        return prev
LeetCode21. Merge Two Sorted Lists
Easy ~15 min☐ solved · https://leetcode.com/problems/merge-two-sorted-lists/
Hint
Dummy head plus two pointers: attach whichever current node is smaller, then move that list forward. When one list runs out, attach the rest of the other.
Solution
class Solution:
    def mergeTwoLists(self, list1: Optional[ListNode], list2: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode()
        tail = dummy
        while list1 and list2:
            if list1.val <= list2.val:
                tail.next = list1
                list1 = list1.next
            else:
                tail.next = list2
                list2 = list2.next
            tail = tail.next
        tail.next = list1 or list2     # whatever is left
        return dummy.next
LeetCode141. Linked List Cycle
Easy ~10 min☐ solved · https://leetcode.com/problems/linked-list-cycle/
Hint
Fast and slow again. If there's no cycle, fast reaches the end. If there is one, fast laps slow and they land on the same node: check slow is fast.
Solution
class Solution:
    def hasCycle(self, head: Optional[ListNode]) -> bool:
        slow = fast = head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
            if slow is fast:         # the fast runner lapped the slow one
                return True
        return False
# O(n) time, O(1) space. A set of seen nodes also works, with O(n) space.
Interesting fact: The Linux kernel is full of linked lists

The Linux kernel keeps its running processes, open files, device drivers and much more in linked lists. They all use one shared design, struct list_head. It is a tiny pair of arrows (next and previous) placed inside each object, instead of a separate box pointing at the object.

Because the arrows live inside the object, one object can sit in several lists at once by holding several pairs of arrows, and adding or removing it never needs extra memory. That's exactly the "O(1) once you're standing next to it" strength from this lesson.

Remember

  • A node has val and next. Walk with while node: node = node.next.
  • Building a list? Use a dummy head and return dummy.next. Re-pointing? Save next first.
  • Slow/fast pointers find the middle and detect cycles in O(1) space.
