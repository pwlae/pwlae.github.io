Binary search trees

Read first: Binary trees: depth-first, Binary search

A binary search tree keeps its values in order, so you can find any value by going left or right at each node, like binary search. It is a normal binary tree with one extra rule.

The idea

Think of a librarian sorting returned books. At each shelf there is a sign: "before M go left, after M go right". At the next shelf there is another sign. You never look at the whole library, you just follow the signs.

A binary search tree (BST) works the same way. The rule, for every node:

  • everything in its left subtree is smaller than it;
  • everything in its right subtree is bigger than it.

To find 6: start at the root 8. 6 is smaller, so go left to 3. 6 is bigger, so go right. Found it. Each step throws away a whole subtree, just like binary search throws away half of a list.

Two more things follow from the rule:

  • In-order is sorted. In-order (left, node, right, from the depth-first lesson) visits all the smaller values, then the node, then the bigger ones. For the tree above: 1 3 6 8 10 14.
  • The shape matters. A search takes one step per level, so it costs O(h), where h is the height of the tree. A nice bushy tree has about log n levels. But insert 1, 2, 3, 4 in that order and every new value goes to the right. The "tree" becomes a linked list, and a search costs O(n).

A balanced tree has about the same height on the left and right of every node. To build one from a sorted list, pick the middle value as the root, then do the same for the left half and the right half. You will do exactly this in problem 108 below.

In Python

Nodes are the same TreeNode class as before. Search is a simple loop, no recursion needed:

def search(node, target):
    while node:
        if target == node.val:
            return node
        # smaller: go left
        if target < node.val:
            node = node.left
        # bigger: go right
        else:
            node = node.right
    # fell off the tree: not there
    return None

Insert walks the same path and hangs the new node where the walk falls off the tree:

def insert(node, val):
    # empty spot: put the node here
    if node is None:
        return TreeNode(val)
    if val < node.val:
        node.left = insert(
            node.left, val)
    else:
        node.right = insert(
            node.right, val)
    return node

Both take O(h) time: about O(log n) if the tree is balanced, O(n) if it is a chain.

Your turn

Each time, ask: can the rule tell me which side to skip?

LeetCode700. Search in a Binary Search Tree
Easy ~5 min☐ solved · https://leetcode.com/problems/search-in-a-binary-search-tree/
Hint
This is the search function above. Return the node itself (the whole subtree), or None.
Solution
class Solution:
    def searchBST(
        self, root: Optional[TreeNode],
        val: int
    ) -> Optional[TreeNode]:
        node = root
        while node:
            if val == node.val:
                return node
            # go to val's side
            if val < node.val:
                node = node.left
            else:
                node = node.right
        return None
# O(h) time, O(1) space.
LeetCode938. Range Sum of BST
Easy ~10 min☐ solved · https://leetcode.com/problems/range-sum-of-bst/
Hint
Plain depth-first sum works. To use the rule: if a node is smaller than low, nothing on its left can be in range, so only go right. If it is bigger than high, only go left.
Solution
class Solution:
    def rangeSumBST(
        self, root: Optional[TreeNode],
        low: int, high: int
    ) -> int:
        if root is None:
            return 0
        # too small: the left side is
        # even smaller, skip it
        if root.val < low:
            return self.rangeSumBST(
                root.right, low, high)
        # too big: skip the right side
        if root.val > high:
            return self.rangeSumBST(
                root.left, low, high)
        # in range: count it, try both
        left = self.rangeSumBST(
            root.left, low, high)
        right = self.rangeSumBST(
            root.right, low, high)
        return root.val + left + right
LeetCode530. Minimum Absolute Difference in BST
Easy ~10 min☐ solved · https://leetcode.com/problems/minimum-absolute-difference-in-bst/
Hint
In-order gives the values sorted. In a sorted list, the closest pair is always two neighbours. Walk in-order and remember the previous value.
Solution
class Solution:
    def getMinimumDifference(
        self, root: Optional[TreeNode]
    ) -> int:
        prev = None
        best = float("inf")

        def walk(node):
            nonlocal prev, best
            if node is None:
                return
            walk(node.left)
            # values arrive sorted here
            if prev is not None:
                gap = node.val - prev
                best = min(best, gap)
            prev = node.val
            walk(node.right)

        walk(root)
        return best
LeetCode108. Convert Sorted Array to Binary Search Tree
Easy ~15 min☐ solved · https://leetcode.com/problems/convert-sorted-array-to-binary-search-tree/
Hint
The middle value is the root. Everything before it goes into the left subtree, everything after it into the right. Build those the same way. Pass indexes lo, hi instead of slicing.
Solution
class Solution:
    def sortedArrayToBST(
        self, nums: List[int]
    ) -> Optional[TreeNode]:

        def build(lo, hi):
            # empty range: no node
            if lo > hi:
                return None
            mid = (lo + hi) // 2
            node = TreeNode(nums[mid])
            node.left = build(
                lo, mid - 1)
            node.right = build(
                mid + 1, hi)
            return node

        return build(0, len(nums) - 1)
# O(n) time. Height is about log n.
LeetCode98. Validate Binary Search Tree
Medium ~20 min☐ solved · https://leetcode.com/problems/validate-binary-search-tree/
Hint
Stretch. Checking each node against its two children is not enough: a node deep on the left must be smaller than the root too. Pass down the allowed range (lo, hi). Going left, the node's value becomes the new hi; going right, the new lo.
Solution
class Solution:
    def isValidBST(
        self, root: Optional[TreeNode]
    ) -> bool:

        def ok(node, lo, hi):
            if node is None:
                return True
            v = node.val
            # must be strictly inside
            if not lo < v < hi:
                return False
            # left side: below v
            # right side: above v
            return (
                ok(node.left, lo, v)
                and
                ok(node.right, v, hi))

        inf = float("inf")
        return ok(root, -inf, inf)
# Another way: in-order must be
# strictly increasing.
Interesting fact: Database indexes are wide search trees

When you add an index to a database table, PostgreSQL, MySQL (InnoDB) and SQLite all store it as a B-tree. It is the default index type in PostgreSQL, and SQLite keeps both its tables and indexes in B-trees.

A B-tree is a search tree where each node is one disk page and holds hundreds of sorted keys instead of one. At each node you pick which of hundreds of children to follow, not just left or right. With 300 keys per node, four levels already cover 300 × 300 × 300 × 300 ≈ 8 billion rows. So finding one row reads only about four pages from disk, and the top levels are usually already in memory.

Remember

  • BST rule: left subtree smaller, right subtree bigger, at every node. Search goes one way per level: O(h).
  • In-order walk of a BST gives the values sorted.
  • Sorted inserts make a chain (O(n)). Build from the middle to keep it balanced (O(log n) height).
