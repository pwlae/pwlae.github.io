Sliding window

Read first: Two pointers, Hash maps and sets

When a problem asks about a stretch of neighbouring items ("the best 4 days in a row", "the longest piece of text without repeats"), don't re-add the whole stretch every time. Slide a window along and update it a little at each step.

The idea

Imagine you're on a train and the window shows exactly 4 houses at a time. When the train moves one house forward, one new house appears at the front and one old house disappears at the back. The other three are still there. You don't have to look at them again.

A sliding window is a stretch of the list from index left to index right. It comes in two kinds:

  • Fixed size: always k items. Each step: add the item coming in, remove the item going out.
  • Growing and shrinking: the right edge moves forward every step. The left edge moves forward only when the window breaks a rule (for example, "no repeated letters").

Fixed-size window

Best sum of 4 neighbours in [1, 12, -5, -6, 50, 3]:

Re-adding 4 numbers for every position would be O(n·k). Updating with one add and one subtract is O(n).

# the first window
window = sum(nums[:k])
best = window
for right in range(k, len(nums)):
    # item coming in
    window += nums[right]
    # item going out
    window -= nums[right - k]
    best = max(best, window)

Growing and shrinking window

Here the window has a rule, and you keep it as big as you can while the rule holds. A set or dict remembers what is inside the window.

left = 0
inside = set()
best = 0
for right, x in enumerate(items):
    # adding x would break the rule...
    while x in inside:
        inside.remove(items[left])
        # ...so shrink from the left
        left += 1
    inside.add(x)
    # window length
    best = max(best, right - left + 1)

It looks like a loop inside a loop, but left only ever moves forward, so it moves at most n times in total. Overall it's still O(n). That's the two-pointers idea again.

Worked example: longest stretch without repeats

LeetCode643. Maximum Average Subarray I
Easy ~10 min☐ solved · https://leetcode.com/problems/maximum-average-subarray-i/
Hint
Fixed window of size k. Find the best sum with the template, then divide by k once at the end.
Solution
class Solution:
    def findMaxAverage(
        self, nums: List[int], k: int
    ) -> float:
        window = sum(nums[:k])
        best = window
        n = len(nums)
        for right in range(k, n):
            window += nums[right]
            window -= nums[right - k]
            best = max(best, window)
        return best / k
LeetCode219. Contains Duplicate II
Easy ~15 min☐ solved · https://leetcode.com/problems/contains-duplicate-ii/
Hint
Keep a set of the last k numbers only. Before adding a number, check whether it's already in the set. After adding, if the set holds more than k numbers, remove the one that fell out of the window: nums[i - k].
Solution
class Solution:
    def containsNearbyDuplicate(
        self, nums: List[int], k: int
    ) -> bool:
        # the last k numbers
        window = set()
        for i, x in enumerate(nums):
            if x in window:
                return True
            window.add(x)
            if len(window) > k:
                # too old: drop it
                old = nums[i - k]
                window.remove(old)
        return False
LeetCode3. Longest Substring Without Repeating Characters
Medium ~20 min☐ solved · https://leetcode.com/problems/longest-substring-without-repeating-characters/
Hint
Stretch problem, but it's exactly the worked example: the growing/shrinking template with a set of letters inside the window.
Solution
class Solution:
    def lengthOfLongestSubstring(
        self, s: str
    ) -> int:
        left = 0
        inside = set()
        best = 0
        for right, ch in enumerate(s):
            # repeat: shrink from left
            while ch in inside:
                inside.remove(s[left])
                left += 1
            inside.add(ch)
            size = right - left + 1
            best = max(best, size)
        return best
Interesting fact: The internet runs on a sliding window

TCP, the protocol that carries web pages, email and most app traffic, uses a sliding window to control speed. The sender may have only a "window" of data sent but not yet confirmed. When the receiver confirms the oldest bytes, the window slides forward and more data can go out.

If the receiver is slow, it shrinks the window, and the sender automatically slows down. That's how a fast server avoids flooding your phone on a weak connection.

Remember

  • Neighbouring stretch of items? Think sliding window: update the window, don't rebuild it.
  • Fixed size: add the new item, remove nums[right - k]. Growing/shrinking: move right every step, move left while the rule is broken.
  • Both are O(n), because each edge only moves forward.
