Greedy choices

Read first: Sorting

A greedy algorithm always takes the choice that looks best right now, and never goes back to change it. When it works, it is the simplest and fastest solution there is.

The idea

You work at a shop till and owe a customer 68p. You don't think hard. You grab the biggest coin that still fits, again and again: 50p, then 10p, then 5p, 2p, 1p. Five coins, and that is the fewest possible.

That is a greedy algorithm. At each step it makes the best-looking local choice (the choice that is best for this one step). It never undoes a choice. It hopes the local choices add up to the best answer overall.

Careful: they don't always. Imagine a country with only 1p, 3p and 4p coins, and you owe 6p.

  • Greedy takes 4p first, then 1p, then 1p: three coins.
  • The best answer is 3p + 3p: two coins.

Taking the 4p looked good, but it was a trap. So greedy needs a reason to be right. Before you trust it, ask yourself one question:

"Is there ever a reason NOT to take this choice now?"

With British coins, the answer is no: a big coin never blocks a better answer. With 1p, 3p, 4p, the answer is yes. When the answer is yes, you need a different tool (dynamic programming solves the coin problem for any coins).

Here is a greedy rule from the problem Lemonade Change below. Lemonade costs $5. A customer pays with $20, so you owe $15. Which notes do you give back?

Why use the $10 first? A $5 can help with any later change. A $10 can only help with a $20. So keeping $5 notes is never worse. Nothing makes you want to hold on to the $10.

In Python

Most greedy solutions have the same shape. Sort first (see Sorting), so the best choice is always next in line. Then make one pass, taking each choice as it comes.

def make_change(amount, coins):
    # biggest coin first
    coins = sorted(coins, reverse=True)
    used = []
    for c in coins:
        # take this coin while it fits
        while amount >= c:
            amount -= c
            used.append(c)
    return used

make_change(68, [1, 2, 5, 10, 20, 50])
# [50, 10, 5, 2, 1]
make_change(6, [1, 3, 4])
# [4, 1, 1]: not the best!

Cost: the sort is O(n log n), and the pass after it is usually O(n). So most greedy solutions are O(n log n) overall, with almost no extra memory.

Worked example

Assign Cookies, the first problem below. Children have greed [1, 2, 3]: each child needs a cookie at least that big. Cookies have sizes [1, 1]. Both lists are sorted. Give the smallest cookie to the least greedy child who is still waiting:

cookiechild needsfits?happy
11yes, next child1
12no, skip cookie1
(none left)stop1

Why is this safe? A small cookie that fits the least greedy child can't do better anywhere else. Bigger cookies stay free for greedier children.

LeetCode455. Assign Cookies
Easy ~10 min☐ solved · https://leetcode.com/problems/assign-cookies/
Hint
Sort both lists. Walk through the cookies with one pointer on the children. If the cookie is big enough for the current child, that child is happy: move to the next child.
Solution
class Solution:
    def findContentChildren(
        self, g: List[int], s: List[int]
    ) -> int:
        g.sort()
        s.sort()
        # child = next child to feed
        child = 0
        for cookie in s:
            if child == len(g):
                break
            if cookie >= g[child]:
                child += 1
        # children fed = happy count
        return child
# O(n log n + m log m) time.
LeetCode2144. Minimum Cost of Buying Candies With Discount
Easy ~10 min☐ solved · https://leetcode.com/problems/minimum-cost-of-buying-candies-with-discount/
Hint
The free candy can be at most the cheaper of the two you pay for. To get the most for free, buy the most expensive ones first. Sort from high to low and skip every third candy.
Solution
class Solution:
    def minimumCost(
        self, cost: List[int]
    ) -> int:
        cost.sort(reverse=True)
        total = 0
        for i, c in enumerate(cost):
            # every 3rd candy is free
            if i % 3 != 2:
                total += c
        return total
# O(n log n) time.
LeetCode1710. Maximum Units on a Truck
Easy ~10 min☐ solved · https://leetcode.com/problems/maximum-units-on-a-truck/
Hint
Every box takes the same space, so load the boxes with the most units first. Sort by units per box, high to low. Take as many as fit, then move on.
Solution
class Solution:
    def maximumUnits(
        self, boxTypes: List[List[int]],
        truckSize: int
    ) -> int:
        # most units per box first
        boxTypes.sort(
            key=lambda b: b[1],
            reverse=True)
        total = 0
        for count, units in boxTypes:
            take = min(count, truckSize)
            total += take * units
            truckSize -= take
            if truckSize == 0:
                break
        return total
# O(n log n) time.
LeetCode860. Lemonade Change
Easy ~15 min☐ solved · https://leetcode.com/problems/lemonade-change/
Hint
Count your $5 and $10 notes ($20s are never given back). Use the diagram above for a $20: prefer a $10 + $5 over three $5s. Return False as soon as you can't give change.
Solution
class Solution:
    def lemonadeChange(
        self, bills: List[int]
    ) -> bool:
        fives = 0
        tens = 0
        for b in bills:
            if b == 5:
                fives += 1
            elif b == 10:
                # owe $5
                if fives == 0:
                    return False
                fives -= 1
                tens += 1
            else:
                # owe $15: use a $10
                # first, keep the $5s
                if tens and fives:
                    tens -= 1
                    fives -= 1
                elif fives >= 3:
                    fives -= 3
                else:
                    return False
        return True
# One pass: O(n) time, O(1) space.
LeetCode122. Best Time to Buy and Sell Stock II
Medium ~15 min☐ solved · https://leetcode.com/problems/best-time-to-buy-and-sell-stock-ii/
Hint
Stretch. You may buy and sell as often as you like. Greedy: take every rise. Whenever tomorrow's price is higher than today's, add the difference.
Solution
class Solution:
    def maxProfit(
        self, prices: List[int]
    ) -> int:
        profit = 0
        # a = today, b = tomorrow
        for a, b in zip(prices,
                        prices[1:]):
            # take every rising day
            if b > a:
                profit += b - a
        return profit
# A long climb from 1 to 5 equals
# the sum of its small daily
# steps, so nothing is missed.
# O(n) time, O(1) space.
Interesting fact: Greedy inside every ZIP file

In 1952, David Huffman, then a student at MIT, found a way to give each symbol (say, a letter) a code made of bits. Common symbols get short codes, rare ones get long codes, so the whole file gets smaller.

His method is greedy. Put every symbol in a pile with its count. Again and again, take the two rarest items and join them into one, until one item is left. That builds a tree, and each symbol's path in the tree is its code. Huffman proved this gives the shortest possible codes of this kind.

Huffman coding is a core part of DEFLATE, the compression used by ZIP and gzip files and inside PNG images (its spec is RFC 1951). Baseline JPEG photos use Huffman coding too.

Remember

  • Greedy: take the best-looking choice now and never go back.
  • Usual shape: sort first, then one pass. Often O(n log n).
  • Only trust it if there is never a reason not to take the choice now (coins 1, 3, 4 for 6 break it).
