Binary search

Read first: Big O in plain words, Arrays: one loop does a lot

Binary search finds something in a sorted list by looking at the middle and throwing away the half that can't hold the answer. A million items take about 20 looks instead of a million.

The idea

Play "guess my number" from 1 to 100. A friend only says "higher" or "lower". The smart first guess is 50. If they say "lower", every number from 50 to 100 is gone in one go. Next guess 25, then 12 or 37, and so on. Each guess cuts what's left in half, so you never need more than 7 guesses (2 × 2 × 2 × 2 × 2 × 2 × 2 = 128, which covers 100).

On a list it works the same way. Keep two markers: lo (the left end of the part still in play) and hi (the right end).

  1. Look at the middle item, mid.
  2. Is it the target? Done.
  3. Too small? The answer is to the right: move lo to mid + 1.
  4. Too big? The answer is to the left: move hi to mid - 1.
  5. If lo passes hi, nothing is left: the target isn't there.

Here is a search for 9 in [1, 3, 5, 7, 9, 11, 13] (indexes 0 to 6):

The catch: this only works when the list is sorted. "Too small, so go right" is only true if everything to the right is bigger. It also works on anything with a single switch point: a row of answers that go "no, no, no, yes, yes, yes". You can binary search for the first "yes".

In Python

One template. Learn it once and use it for every problem in this lesson.

def binary_search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:   # still in play
        mid = (lo + hi) // 2  # middle
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            lo = mid + 1  # go right
        else:
            hi = mid - 1  # go left
    return -1  # lo passed hi

Each loop throws away half of what's left, so the cost is O(log n) time (see Big O) and O(1) extra space.

Variant: find the first "yes"

Sometimes you don't want an exact match. You want the first place where something becomes true: the first bad version, the first number ≥ target. Two small changes: loop while lo < hi, and when mid is a "yes", keep it with hi = mid (it might be the answer).

def first_yes(lo, hi, is_yes):
    while lo < hi:
        mid = (lo + hi) // 2
        if is_yes(mid):
            hi = mid      # keep mid
        else:
            lo = mid + 1  # skip mid
    return lo  # lo == hi: first yes

Python has this built in. bisect.bisect_left(nums, x) returns the first index where nums[i] >= x, which is where x would go to keep the list sorted.

import bisect
nums = [1, 3, 5, 7]
bisect.bisect_left(nums, 5)  # 2
bisect.bisect_left(nums, 4)  # 2

Both give 2: 5 is at index 2, and 4 would also go at index 2, just before the 5.

LeetCode374. Guess Number Higher or Lower
Easy ~10 min☐ solved · https://leetcode.com/problems/guess-number-higher-or-lower/
Hint
The number game from the top of the lesson. There's no list: lo = 1, hi = n. Read carefully what guess(mid) returns: -1 means your guess is too high.
Solution
class Solution:
    def guessNumber(
        self, n: int
    ) -> int:
        lo, hi = 1, n
        while lo <= hi:
            mid = (lo + hi) // 2
            res = guess(mid)
            if res == 0:
                return mid
            elif res == -1:  # too high
                hi = mid - 1
            else:  # res == 1: too low
                lo = mid + 1
        return -1  # never reached

LeetCode278. First Bad Version
Easy ~10 min☐ solved · https://leetcode.com/problems/first-bad-version/
Hint
The versions go good, good, good, bad, bad. That's a switch point. Use the "first yes" variant with lo = 1, hi = n, and isBadVersion(mid) as the "yes" test.
Solution
class Solution:
    def firstBadVersion(
        self, n: int
    ) -> int:
        lo, hi = 1, n
        while lo < hi:
            mid = (lo + hi) // 2
            if isBadVersion(mid):
                # bad: maybe first
                hi = mid
            else:
                # good: skip
                lo = mid + 1
        return lo
LeetCode69. Sqrt(x)
Easy ~15 min☐ solved · https://leetcode.com/problems/sqrtx/
Hint
Search the answer, not a list. Try numbers mid from 0 to x. If mid * mid <= x, it's a possible answer: remember it and try bigger. Otherwise try smaller.
Solution
class Solution:
    def mySqrt(self, x: int) -> int:
        lo, hi = 0, x
        ans = 0
        while lo <= hi:
            mid = (lo + hi) // 2
            if mid * mid <= x:
                # fits; try bigger
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1  # too big
        return ans
# O(log x) time. Works for x = 0
# and x = 1 too.
Interesting fact: git bisect: binary search for bugs

Git has a command called git bisect. Its manual describes it as "use binary search to find the commit that introduced a bug". You tell it one commit where the code worked ("good") and one where it's broken ("bad").

Git then checks out the commit in the middle. You test it and type git bisect good or git bisect bad, and Git throws away half the history. With 1,000 commits in between you test only about 10 of them, because 2 to the power 10 is 1,024. You can even hand it a test script with git bisect run and let it find the bad commit on its own.

Remember

  • Binary search halves what's left each step: O(log n). It needs sorted data or a single "no → yes" switch point.
  • Exact match: while lo <= hi, then lo = mid + 1 or hi = mid - 1.
  • First "yes": while lo < hi, then hi = mid or lo = mid + 1. Python's bisect_left does it for you.
