A graph is a set of places joined by connections: stations and tracks, people and friendships, pixels and their neighbours. Learn to walk a graph and a huge family of problems opens up.

The idea

Look at the Tube map. Each station is a node (a place). Each stretch of track between two stations is an edge (a connection). That is all a graph is. Here are five stations in central London (some stops in between are left out):

You already know one kind of graph: a tree. A tree is a graph with no loops. Graphs can have loops: Waterloo → Westminster → Embankment → Waterloo. That one difference matters a lot. If you walk a graph the way you walk a tree, you go round that loop for ever.

The fix is a visited set (see Hash maps and sets). Before you step onto a node, check: "have I been here?" If yes, skip it.

Storing a graph. Problems usually give you a list of edges, like [[0, 1], [1, 2]]. Turn it into an adjacency list: a dict from each node to the list of its neighbours. "Adjacent" just means "next to".

Grids are graphs too. A grid of cells (an image, a map of land and sea) is a graph where each cell's neighbours are the cells up, down, left and right. No need to build a dict: you work out the neighbours from the row and column.

Walking a graph works just like trees:

  1. DFS (depth-first): go as deep as you can, then back up. Use recursion or a stack.
  2. BFS (breadth-first): visit everything 1 step away, then 2 steps, and so on. Use a queue.

Both mark each node as visited the moment they reach it.

In Python

from collections import defaultdict
from collections import deque

def build(edges):
    # node -> list of neighbours
    graph = defaultdict(list)
    for a, b in edges:
        # undirected: both ways
        graph[a].append(b)
        graph[b].append(a)
    return graph

def bfs(graph, start):
    visited = {start}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        for nxt in graph[node]:
            if nxt not in visited:
                visited.add(nxt)
                queue.append(nxt)
    return visited

def dfs(graph, node, visited):
    visited.add(node)
    for nxt in graph[node]:
        if nxt not in visited:
            dfs(graph, nxt, visited)

Cost: every node is visited once and every edge is looked at twice (once from each end). With V nodes and E edges that is O(V + E) time, and O(V) memory for the visited set and the queue.

Your turn

The first one needs no walking at all, only counting edges. Then three walks.

Each pair [a, b] is an arrow: a trusts b. The judge trusts nobody (no arrows out) and everyone else trusts them (n − 1 arrows in). Count arrows in and out for each person. 
class Solution:
    def findJudge(
        self, n: int,
        trust: List[List[int]]
    ) -> int:
        # score = arrows in - arrows out
        score = [0] * (n + 1)
        for a, b in trust:
            score[a] -= 1
            score[b] += 1
        for p in range(1, n + 1):
            # n - 1 in, 0 out
            if score[p] == n - 1:
                return p
        return -1
# O(n + len(trust)) time.
Build the adjacency list, then BFS (or DFS) from source. Is destination in the visited set at the end? 
class Solution:
    def validPath(
        self, n: int,
        edges: List[List[int]],
        source: int,
        destination: int
    ) -> bool:
        graph = defaultdict(list)
        for a, b in edges:
            graph[a].append(b)
            graph[b].append(a)
        visited = {source}
        queue = deque([source])
        while queue:
            node = queue.popleft()
            if node == destination:
                return True
            for nxt in graph[node]:
                if nxt not in visited:
                    visited.add(nxt)
                    queue.append(nxt)
        return False
# O(n + len(edges)) time.
It's a grid graph. From (sr, sc), DFS to the up/down/left/right cells that still have the starting colour, and paint them. Careful: if the new colour equals the old one, return at once, or you loop for ever. 
class Solution:
    def floodFill(
        self, image: List[List[int]],
        sr: int, sc: int, color: int
    ) -> List[List[int]]:
        old = image[sr][sc]
        if old == color:
            return image
        rows = len(image)
        cols = len(image[0])

        def dfs(r, c):
            if not (0 <= r < rows):
                return
            if not (0 <= c < cols):
                return
            if image[r][c] != old:
                return
            # painting = marking visited
            image[r][c] = color
            dfs(r + 1, c)
            dfs(r - 1, c)
            dfs(r, c + 1)
            dfs(r, c - 1)

        dfs(sr, sc)
        return image
# O(rows * cols) time.
Stretch. Scan every cell. When you find land ("1") you haven't visited, that's a new island: count it, then DFS to sink the whole island (turn it to "0") so you don't count it again. 
class Solution:
    def numIslands(
        self, grid: List[List[str]]
    ) -> int:
        rows = len(grid)
        cols = len(grid[0])

        def sink(r, c):
            if not (0 <= r < rows):
                return
            if not (0 <= c < cols):
                return
            if grid[r][c] != "1":
                return
            # mark as visited
            grid[r][c] = "0"
            sink(r + 1, c)
            sink(r - 1, c)
            sink(r, c + 1)
            sink(r, c - 1)

        count = 0
        for r in range(rows):
            for c in range(cols):
                if grid[r][c] == "1":
                    count += 1
                    sink(r, c)
        return count
# O(rows * cols) time.

The "paint bucket" tool in image editors is the Flood Fill problem above. In GIMP, the Bucket Fill tool's manual says that in "Fill similar colors" mode the fill starts at the pixel you click and spreads until the colour becomes "too different". A threshold setting decides how different is too different, and so how far the fill spreads.

In graph words: pixels are nodes, touching pixels are edges, and "close enough in colour" decides which edges you may walk. The image is a grid graph, and the fill is a walk from one start cell, exactly like LeetCode 733.
  • Graph = nodes + edges. Store it as a dict: node → list of neighbours.
  • BFS and DFS on a graph = the tree versions plus a visited set. Cost O(V + E).
  • Grids are graphs: neighbours are up, down, left, right. Count islands by starting a walk from each unvisited land cell.
