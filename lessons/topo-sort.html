Some jobs must happen before others: socks before shoes, a library before the app that uses it. Topological sort finds an order that keeps every "before" rule, or tells you that no such order exists.

The idea

Think about getting dressed in the morning. You can't put shoes on before socks, or a tie on before a shirt. Some things don't care: socks and shirt can go in either order. You want one order that breaks no rule.

Draw each item as a node (see Graphs). Draw an arrow from A to B when A must come before B. Arrows go one way only, so this is a directed graph.

%%{init: {"flowchart": {"rankSpacing": 30, "nodeSpacing": 16, "padding": 6}}}%%
flowchart LR
  P["Pants"] --> T["Trousers"]
  T --> SH["Shoes"]
  S["Socks"] --> SH
  SI["Shirt"] --> TI["Tie"]

One valid order: Pants, Socks, Shirt, Trousers, Tie, Shoes. There are others. Any order is fine, as long as every arrow points forward.

In-degree. A node's in-degree is the number of arrows pointing into it: how many things must happen first. Shoes has in-degree 2 (Trousers and Socks). Pants, Socks and Shirt have in-degree 0: nothing has to come before them, so you can start with any of them.

Kahn's algorithm turns this into steps:

  1. Count the in-degree of every node.
  2. Put every node with in-degree 0 in a queue. These are ready.
  3. Take a node from the queue and add it to the order. "Done" with it.
  4. For each arrow out of it, lower the neighbour's in-degree by 1. If it drops to 0, the neighbour is now ready: add it to the queue.
  5. Repeat until the queue is empty.

The impossible case. What if the rules go round in a circle? A before B, B before C, C before A. That is a cycle.

%%{init: {"flowchart": {"rankSpacing": 30, "nodeSpacing": 20, "padding": 6}}}%%
flowchart LR
  A["A"] --> B["B"]
  B --> C["C"]
  C --> A

Every node in the circle waits for another one, so none ever reaches in-degree 0. Kahn's algorithm stops early. So the check is simple: if the order has fewer nodes than the graph, there is a cycle, and no valid order exists.

In Python

from collections import defaultdict
from collections import deque

def topo_sort(n, edges):
    # edges: [a, b] means a before b
    graph = defaultdict(list)
    indeg = [0] * n
    for a, b in edges:
        graph[a].append(b)
        indeg[b] += 1

    # everything with nothing before it
    queue = deque(
        i for i in range(n)
        if indeg[i] == 0
    )
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nxt in graph[node]:
            indeg[nxt] -= 1
            if indeg[nxt] == 0:
                # all "befores" done
                queue.append(nxt)

    if len(order) < n:
        return []  # cycle: impossible
    return order

Cost: each node goes into the queue once and each arrow is looked at once. With V nodes and E edges that is O(V + E) time, the same as BFS, and O(V + E) memory for the graph.

Your turn

The first two only need in-degree and out-degree counting. Then the full algorithm twice. Topological sort problems on LeetCode are mostly Medium, but they all use the template above.

Each path is an arrow from one city to another. The destination is the city with no arrow going out of it. Put every starting city in a set, then find the end city that is not in it. 
class Solution:
    def destCity(
        self, paths: List[List[str]]
    ) -> str:
        # cities with an arrow out
        starts = {a for a, b in paths}
        for a, b in paths:
            if b not in starts:
                return b
# O(n) time.
Looks scary, is short. A node with an arrow pointing into it can be reached from somewhere else. A node with in-degree 0 can't, so you must start there. Return every node with in-degree 0. 
class Solution:
    def findSmallestSetOfVertices(
        self, n: int,
        edges: List[List[int]]
    ) -> List[int]:
        indeg = [0] * n
        for a, b in edges:
            indeg[b] += 1
        # nothing points to these
        return [
            i for i in range(n)
            if indeg[i] == 0
        ]
# O(n + len(edges)) time.
Courses are nodes. [a, b] means "take b before a", so the arrow goes b → a. Run Kahn's algorithm and count how many courses you place. Can you finish? Only if you placed all of them. 
class Solution:
    def canFinish(
        self, numCourses: int,
        prerequisites: List[List[int]]
    ) -> bool:
        graph = defaultdict(list)
        indeg = [0] * numCourses
        for a, b in prerequisites:
            # b must come before a
            graph[b].append(a)
            indeg[a] += 1

        queue = deque()
        for i in range(numCourses):
            if indeg[i] == 0:
                queue.append(i)
        taken = 0
        while queue:
            node = queue.popleft()
            taken += 1
            for nxt in graph[node]:
                indeg[nxt] -= 1
                if indeg[nxt] == 0:
                    queue.append(nxt)
        # fewer means a cycle
        return taken == numCourses
# O(V + E) time.

class Solution:
    def findOrder(
        self, numCourses: int,
        prerequisites: List[List[int]]
    ) -> List[int]:
        graph = defaultdict(list)
        indeg = [0] * numCourses
        for a, b in prerequisites:
            graph[b].append(a)
            indeg[a] += 1

        queue = deque()
        for i in range(numCourses):
            if indeg[i] == 0:
                queue.append(i)
        order = []
        while queue:
            node = queue.popleft()
            order.append(node)
            for nxt in graph[node]:
                indeg[nxt] -= 1
                if indeg[nxt] == 0:
                    queue.append(nxt)
        if len(order) < numCourses:
            return []  # cycle
        return order
# O(V + E) time.

A build tool like Make reads rules such as "app needs main.o and util.o". Each rule is an arrow in a dependency graph. Make builds every prerequisite before the thing that needs it, which is a topological order. If the rules loop, GNU Make tells you so with a message like Circular app <- main.o dependency dropped. That is the cycle case from Kahn's algorithm.

Package managers such as pip and npm face the same problem when they install a library and everything it depends on. Python even ships the algorithm: the standard graphlib.TopologicalSorter (since Python 3.9) gives you nodes in a valid order and raises a CycleError if there is a loop.
  • Topological sort = an order where every arrow "A before B" points forward.
  • Kahn's algorithm: queue all in-degree 0 nodes, take one, lower its neighbours' in-degree, queue any that reach 0. O(V + E).
  • If fewer nodes come out than went in, there is a cycle and no valid order exists.
