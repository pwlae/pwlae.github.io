Instead of one loop variable, use two indexes that move through the list together. This turns many "check every pair" problems into a single pass, and often needs no extra list at all.

The idea

There are two flavours. Learn both, because they come up everywhere.

1. Opposite ends, walking inwards. Picture two people starting at opposite ends of a train platform and walking towards each other, comparing what they see, until they meet in the middle. That's how you check whether a word reads the same backwards:

flowchart TD
  A["L=0 'r'  ·  R=6 'r'  →  match"] --> B["L=1 'a'  ·  R=5 'a'  →  match"]
  B --> C["L=2 'c'  ·  R=4 'c'  →  match"]
  C --> D["L=3, R=3: pointers met
it's a palindrome"]

2. Slow and fast, same direction. One pointer (read) visits every item. The other (write) only moves when you keep an item. Everything to the left of write is "the answer so far". It's like tidying a bookshelf in one pass: you look at every book, but only the keepers get pushed to the front.

In Python

# Flavour 1: opposite ends
left, right = 0, len(nums) - 1
while left < right:
    # look at nums[left] and nums[right], then move one or both
    left += 1
    right -= 1

# Flavour 2: slow (write) and fast (read)
write = 0
for read in range(len(nums)):
    if keep(nums[read]):
        nums[write] = nums[read]
        write += 1
# nums[:write] now holds the kept items

Each pointer only moves forward (or only backward), so together they take at most n steps: O(n) time. They change the list where it is ("in place"), so O(1) extra space.

Worked example: Move Zeroes

Push all zeros in [0, 1, 0, 3, 12] to the end, keeping the other numbers in order. read walks every item. When it finds a non-zero, swap it into position write and move write on.

The first three use opposite ends, the next two use slow/fast, and the last one walks backwards.

Opposite ends: swap s[left] and s[right], then move both inwards. In Python, a, b = b, a swaps two values. 
class Solution:
    def reverseString(self, s: List[str]) -> None:
        left, right = 0, len(s) - 1
        while left < right:
            s[left], s[right] = s[right], s[left]
            left += 1
            right -= 1
Same as the racecar picture, but first skip anything that isn't a letter or digit (ch.isalnum()) and compare with .lower(). 
class Solution:
    def isPalindrome(self, s: str) -> bool:
        left, right = 0, len(s) - 1
        while left < right:
            if not s[left].isalnum():
                left += 1
            elif not s[right].isalnum():
                right -= 1
            elif s[left].lower() != s[right].lower():
                return False
            else:
                left += 1
                right -= 1
        return True
Negative numbers make big squares too, so the biggest square is at one of the two ends. Compare the ends, put the bigger square at the back of the result, and move that pointer inwards. 
class Solution:
    def sortedSquares(self, nums: List[int]) -> List[int]:
        n = len(nums)
        result = [0] * n
        left, right = 0, n - 1
        for pos in range(n - 1, -1, -1):      # fill from the back
            if abs(nums[left]) > abs(nums[right]):
                result[pos] = nums[left] ** 2
                left += 1
            else:
                result[pos] = nums[right] ** 2
                right -= 1
        return result
# O(n). The easy way, sorted(x * x for x in nums), is O(n log n): also accepted.
Exactly the worked example: read visits everything, non-zeros get swapped to write. 
class Solution:
    def moveZeroes(self, nums: List[int]) -> None:
        write = 0
        for read in range(len(nums)):
            if nums[read] != 0:
                nums[write], nums[read] = nums[read], nums[write]
                write += 1
The list is sorted, so duplicates sit next to each other. Keep a number only if it differs from the last kept number, nums[write - 1]. Return write. 
class Solution:
    def removeDuplicates(self, nums: List[int]) -> int:
        write = 1                       # the first number is always kept
        for read in range(1, len(nums)):
            if nums[read] != nums[write - 1]:
                nums[write] = nums[read]
                write += 1
        return write
Filling from the front would overwrite numbers you still need. Fill from the back instead: one pointer at the end of each list's real numbers, and a third at the very end of nums1. Put the bigger of the two there. 
class Solution:
    def merge(self, nums1: List[int], m: int, nums2: List[int], n: int) -> None:
        i, j = m - 1, n - 1              # last real number in each list
        for pos in range(m + n - 1, -1, -1):
            # take from nums2 if nums1 is used up, or nums2's number is bigger
            if i < 0 or (j >= 0 and nums2[j] > nums1[i]):
                nums1[pos] = nums2[j]
                j -= 1
            else:
                nums1[pos] = nums1[i]
                i -= 1

The command-line tools comm and join compare two files line by line. Both need the files to be sorted first, and that's the clue: they work like Merge Sorted Array. They keep one pointer in each file, compare the two current lines, and move the smaller one forward.

Because they only ever hold the current lines, they can compare files much bigger than the computer's memory. Databases use the same idea in a "merge join" to match up rows from two sorted tables.
  • Opposite ends (left, right moving inwards): reversing, palindromes, sorted-pair questions.
  • Slow/fast (write keeps, read scans): remove or move items in place.
  • Both are O(n) time, O(1) extra space. When filling a list in place, try filling from the back.
