A stack is a pile where you only touch the top. It's the right tool whenever the most recent unfinished thing is the one you need next: matching brackets, undo, "cancel the last one".

The idea

Think of a stack of plates in a canteen. You put a clean plate on top, and you take a plate from the top. You never pull one out of the middle. The last plate in is the first plate out ("last in, first out").

Three operations, all instant:

  • push: put something on top
  • pop: take the top thing off
  • peek: look at the top without taking it

In Python

A plain list is already a stack. The end of the list is the top.

stack = []
stack.append(3)  # push -> [3]
stack.append(7)  # push -> [3, 7]
stack[-1]        # peek -> 7
stack.pop()      # pop -> 7, now [3]
# pop on an empty list is an error,
# so check first: is it non-empty?
if stack:
    ...

append, pop() and [-1] are all O(1). Avoid pop(0), which takes from the bottom and is slow (that's a queue, next lesson).

When to think "stack"

  • Things come in pairs that nest, like ( [ ] ): the most recent opener must close first.
  • A new item can cancel the previous one, like "undo" or deleting the last character.
  • You need "the most recent item that is still waiting for something".

Worked example: matching brackets

Is "({[]})" correctly matched? Push every opener. On a closer, the top of the stack must be its partner: pop it. At the end, the stack must be empty.

flowchart TD
  A["read ( → push · stack: ("] --> B["read { → push · stack: ( {"]
  B --> C["read [ → push · stack: ( { ["]
  C --> D["read ] → top is [ ✓ pop · stack: ( {"]
  D --> E["read } → top is { ✓ pop · stack: ("]
  E --> F["read ) → top is ( ✓ pop · stack: empty"]
  F --> G["empty at the end → valid"]

It fails if a closer arrives when the stack is empty, if the top is the wrong opener, or if anything is left at the end.

Keep the valid scores on a stack. "C" pops the last score, "D" pushes double the top, "+" pushes the sum of the top two, and anything else is a number to push. 
class Solution:
    def calPoints(
        self, operations: List[str]
    ) -> int:
        stack = []
        for op in operations:
            if op == "C":
                # cancel the last score
                stack.pop()
            elif op == "D":
                last = stack[-1]
                stack.append(last * 2)
            elif op == "+":
                # sum of the last two
                total = sum(stack[-2:])
                stack.append(total)
            else:
                stack.append(int(op))
        return sum(stack)
The worked example. A dict from each closer to its opener helps: {")": "(", "]": "[", "}": "{"}. 
class Solution:
    def isValid(self, s: str) -> bool:
        partner = {")": "(",
                   "]": "[",
                   "}": "{"}
        stack = []
        for ch in s:
            # a closer
            if ch in partner:
                if not stack:
                    return False
                top = stack.pop()
                if top != partner[ch]:
                    return False
            else:  # an opener
                stack.append(ch)
        # nothing left open
        return not stack
Push letters one by one. If the new letter equals the top of the stack, they cancel: pop instead of pushing. Join the stack at the end. 
class Solution:
    def removeDuplicates(
        self, s: str
    ) -> str:
        # the letters kept, as a stack
        kept = []
        for ch in s:
            if kept and kept[-1] == ch:
                # the pair cancels out
                kept.pop()
            else:
                kept.append(ch)
        return "".join(kept)
Store pairs on the stack: (value, smallest value so far). When you push, the new "smallest so far" is min(value, previous smallest). Then getMin just reads the top pair. 
class MinStack:
    def __init__(self):
        # each item: (value, min of
        # everything up to here)
        self.stack = []

    def push(self, val: int) -> None:
        smallest = val
        if self.stack:
            # min of everything below
            below = self.stack[-1][1]
            smallest = min(val, below)
        pair = (val, smallest)
        self.stack.append(pair)

    def pop(self) -> None:
        self.stack.pop()

    def top(self) -> int:
        return self.stack[-1][0]

    def getMin(self) -> int:
        return self.stack[-1][1]
Keep a stack of days still waiting for a warmer day (store their indexes). For each new day, while it's warmer than the day on top of the stack, that waiting day has found its answer: pop it and record the distance. Then push today. 
class Solution:
    def dailyTemperatures(
        self, temperatures: List[int]
    ) -> List[int]:
        temps = temperatures
        answer = [0] * len(temps)
        # indexes of days with no
        # warmer day yet
        waiting = []
        for i, t in enumerate(temps):
            while waiting:
                day = waiting[-1]
                # not warmer: stop here
                if temps[day] >= t:
                    break
                waiting.pop()
                # found its warmer day
                answer[day] = i - day
            waiting.append(i)
        return answer
# Each day is pushed once and popped
# at most once: O(n).
# This is called a "monotonic stack":
# temperatures on it only go down.

When a function calls another function, the computer needs to remember where to come back to. It pushes a "frame" (the function's local variables and return point) onto the call stack. When the function returns, its frame is popped and the caller carries on.

If functions keep calling deeper and deeper without returning, the stack runs out. That's a stack overflow, the error the famous programming website is named after. Python stops you earlier, at about 1,000 nested calls by default (sys.getrecursionlimit()), and raises RecursionError. You'll meet that in the Recursion lesson.
  • Stack = last in, first out. In Python: append, pop(), [-1], all O(1).
  • Use it for nesting pairs, cancelling the previous item, and "most recent item still waiting".
  • Always check if stack: before popping or peeking.
