Inside the computer, every number is a row of 0s and 1s called bits. A few small tricks with bits solve some problems in one line, with no extra memory.

The idea

Picture a row of light switches. Each switch is worth a number: from the right, 1, 2, 4, 8, and each next one is worth double. A switch that is on is a 1. A switch that is off is a 0. Add up the switches that are on, and you get the number.

on: 1"] --- B["4
on: 1"] --- C["2
off: 0"] --- D["1

So 13 is 1101 in binary (numbers written with only 0 and 1). Python shows it with bin:

bin(13)    # '0b1101'
bin(5)     # '0b101'
int("101", 2)  # 5, back again

The 0b at the front only means "this is binary".

The operators

Bit operators look at two numbers switch by switch, lined up from the right:

  • a & b (AND): 1 where both are 1.
  • a | b (OR): 1 where either is 1.
  • a ^ b (XOR): 1 where they are different.
  • a << 1: slide every bit one place left. That doubles the number.
  • a >> 1: slide every bit one place right. That halves it (rounding down).
aba & ba | ba ^ b
00000
01011
10011
11110

Three tricks

You only need three tricks for the problems below.

1. Pairs cancel: x ^ x == 0. A number XOR itself has no different bits, so it is 0. And x ^ 0 == x. Order does not matter. So if you XOR a list where every number appears twice except one, the pairs vanish and the lonely number is left:

%%{init: {"flowchart": {"rankSpacing": 26, "nodeSpacing": 20, "padding": 6}}}%%
flowchart TD
  A["start: 5 = 101"] --> B["^ 3 = 011
result 110 = 6"]
  B --> C["^ 5 = 101
result 011 = 3"]
  C --> D["the 5s cancel:
3 is left"]

2. Drop the lowest 1: x & (x - 1). Taking 1 away flips the lowest 1-bit to 0 and every 0 to its right to 1. AND keeps only what both share, so the lowest 1 disappears:

x = 12       # 1100
x - 1        # 1011
x & (x - 1)  # 1000 = 8

3. Odd or even: x & 1. The switch worth 1 is the only odd one. So x & 1 is 1 for odd numbers and 0 for even ones.

In Python

Here are the tricks as a small toolbox you can copy:

def lonely(nums):
    # every number twice but one
    ans = 0
    for x in nums:
        # pairs cancel out
        ans ^= x
    return ans

def count_ones(x):
    count = 0
    while x:
        # drop the lowest 1-bit
        x &= x - 1
        count += 1
    return count

def is_odd(x):
    return x & 1 == 1

lonely([5, 3, 5])   # 3
count_ones(13)      # 3 (1101)
is_odd(13)          # True

Cost: lonely is one pass, O(n) time and O(1) space. count_ones loops once per 1-bit. A LeetCode number has at most 32 bits, so that is O(1).

Your turn

For each problem, ask: "which of the three tricks fits?"

Every number appears twice except one. Trick 1: XOR them all together. 
class Solution:
    def singleNumber(
        self, nums: List[int]
    ) -> int:
        ans = 0
        for x in nums:
            # pairs cancel: x ^ x == 0
            ans ^= x
        return ans
# O(n) time, O(1) space.
Trick 2: while n is not 0, drop its lowest 1-bit and count how many times you did it. 
class Solution:
    def hammingWeight(
        self, n: int
    ) -> int:
        count = 0
        while n:
            # remove the lowest 1-bit
            n &= n - 1
            count += 1
        return count
# One step per 1-bit: O(1).
# Also fine: bin(n).count("1")
You need the places where x and y are different. XOR puts a 1 exactly there. Then count the 1s, like the problem above. 
class Solution:
    def hammingDistance(
        self, x: int, y: int
    ) -> int:
        # 1 where the bits differ
        diff = x ^ y
        count = 0
        while diff:
            diff &= diff - 1
            count += 1
        return count
# O(1): at most 32 bits.
XOR every index 0..n and every number in the list. Each number that is there meets its partner and cancels. Only the missing one is left. (Adding up and subtracting also works.) 
class Solution:
    def missingNumber(
        self, nums: List[int]
    ) -> int:
        # start with n itself
        ans = len(nums)
        for i, x in enumerate(nums):
            # i and x cancel if paired
            ans ^= i ^ x
        return ans
# O(n) time, O(1) space.
Build the answer list from 0 upwards. i & (i - 1) is a smaller number with one 1-bit less, and you already know its count. Add 1. 
class Solution:
    def countBits(
        self, n: int
    ) -> List[int]:
        ans = [0] * (n + 1)
        for i in range(1, n + 1):
            # i without its lowest 1
            # is smaller: already done
            prev = i & (i - 1)
            ans[i] = ans[prev] + 1
        return ans
# One pass: O(n) time.

On Linux and macOS, every file has 9 permission bits: read, write and execute (run it as a program), for three groups of people: the owner, the file's group, and everyone else.

The chmod command lets you set them with digits. Each digit is three switches: read is worth 4, write 2, execute 1. So chmod 755 file means:

  • owner 7 = 4 + 2 + 1: read, write, execute.
  • group 5 = 4 + 1: read and execute.
  • others 5 = 4 + 1: read and execute.

And chmod 644 is the usual one for a plain file: the owner reads and writes, everyone else only reads. These values are fixed by the POSIX standard's chmod page, so they work the same on every Unix-like system.
  • Binary is a row of switches worth 1, 2, 4, 8… & both, | either, ^ different.
  • x ^ x == 0: XOR a list and the pairs cancel.
  • x & (x - 1) drops the lowest 1-bit. x & 1 tells odd from even.
