When the connections in a graph have different lengths, like minutes between Tube stations, Dijkstra's algorithm finds the quickest way from one place to every other place. It is BFS with a heap instead of a queue.

The idea

In Graphs, BFS found the path with the fewest stops. That is the right answer when every edge costs the same. On the Tube it doesn't: some hops take 1 minute, some take 9. Now each edge has a number on it, called its weight (here: minutes). A graph like this is a weighted graph.

Here are five stations again. The minutes are made up to keep the sums easy.

From Bank, BFS says "Embankment is 1 stop away". True, but that stop takes 9 minutes. Going Bank → London Bridge → Waterloo → Embankment is 3 stops and only 2 + 3 + 2 = 7 minutes. Fewest stops is not quickest.

Dijkstra's rule: always deal next with the closest place you haven't finished yet. Picture ink spreading from Bank along the tracks at one minute per minute. The ink reaches stations in order of how far they are. Whatever it reaches first, it reached by the quickest way.

  1. Keep dist: the best time found so far to each station. Start: dist[Bank] = 0.
  2. Keep a min-heap of (time, station). The heap always hands you the smallest time first.
  3. Pop the closest station. For each neighbour, try "my time + edge weight". If that beats the neighbour's dist, write it down and push it onto the heap.
  4. Repeat until the heap is empty.

One catch: a station can sit in the heap twice, once with an old, worse time. When you pop an entry whose time is bigger than dist[station], it is stale (out of date). Just skip it.

In Python

The graph is an adjacency list as before, but each neighbour comes with its weight: graph[a] is a list of (b, minutes) pairs.

from heapq import heappush, heappop
from collections import defaultdict

INF = float("inf")

def build(edges):
    graph = defaultdict(list)
    for a, b, w in edges:
        # undirected: both ways
        graph[a].append((b, w))
        graph[b].append((a, w))
    return graph

def dijkstra(graph, start):
    # best time found so far
    dist = {start: 0}
    heap = [(0, start)]
    while heap:
        d, node = heappop(heap)
        if d > dist[node]:
            continue  # stale, skip
        for nxt, w in graph[node]:
            nd = d + w
            if nd < dist.get(nxt, INF):
                dist[nxt] = nd
                heappush(heap,
                         (nd, nxt))
    # places missing from dist
    # can't be reached at all
    return dist

Tuples compare by their first item, so the heap orders entries by time. Cost: each edge can push at most one entry, and each push or pop on the heap costs O(log E). With E edges that is O(E log E) time and O(V + E) memory.

Limit: Dijkstra needs every weight to be zero or more. With a negative weight, a "finished" place could still get cheaper later, and the answer can be wrong.

Dijkstra problems on LeetCode start at Medium, so all three are Medium. The first is the template almost as is. The next two change what "distance" means. Give each one its time box, then read the solution and move on.

Edges here are one-way: [u, v, w] means u → v only. Run the template from k. If dist has fewer than n nodes, someone was never reached: return −1. Otherwise the answer is the biggest value in dist. 
from heapq import heappush, heappop

class Solution:
    def networkDelayTime(
        self, times: List[List[int]],
        n: int, k: int
    ) -> int:
        graph = defaultdict(list)
        for u, v, w in times:
            # one-way: u -> v
            graph[u].append((v, w))

        INF = float("inf")
        dist = {k: 0}
        heap = [(0, k)]
        while heap:
            d, node = heappop(heap)
            if d > dist[node]:
                continue  # stale
            # v: a neighbour of node
            for v, w in graph[node]:
                nd = d + w
                old = dist.get(v, INF)
                if nd >= old:
                    continue
                dist[v] = nd
                heappush(heap, (nd, v))

        if len(dist) < n:
            # not all reached
            return -1
        # everyone has the signal once
        # the slowest node has it
        return max(dist.values())
# O(E log E) time.
Same idea, flipped. Along a path you multiply probabilities, and you want the biggest result. Multiplying by a number ≤ 1 never makes it bigger, so "best first" still works. Python's heap pops the smallest, so push -prob to pop the biggest first. 
from heapq import heappush, heappop

class Solution:
    def maxProbability(
        self, n: int,
        edges: List[List[int]],
        succProb: List[float],
        start_node: int, end_node: int
    ) -> float:
        graph = defaultdict(list)
        for i in range(len(edges)):
            a, b = edges[i]
            p = succProb[i]
            graph[a].append((b, p))
            graph[b].append((a, p))

        best = {start_node: 1.0}
        # negate: biggest pops first
        heap = [(-1.0, start_node)]
        while heap:
            neg, node = heappop(heap)
            p = -neg
            if node == end_node:
                return p  # best
            if p < best[node]:
                continue  # stale
            # v: a neighbour of node
            for v, q in graph[node]:
                np = p * q
                old = best.get(v, 0.0)
                if np <= old:
                    continue
                best[v] = np
                heappush(heap,
                         (-np, v))
        return 0.0  # no path
# O(E log E) time.
Stretch. Each cell is a node; its neighbours are up, down, left, right. The "length" of a path is not a sum: it is the biggest single step on it. So the new distance is max(d, abs(height difference)) instead of d + w. Everything else is the template. 
from heapq import heappush, heappop

class Solution:
    def minimumEffortPath(
        self, heights: List[List[int]]
    ) -> int:
        rows = len(heights)
        cols = len(heights[0])
        goal = (rows - 1, cols - 1)
        steps = ((1, 0), (-1, 0),
                 (0, 1), (0, -1))
        INF = float("inf")
        dist = {(0, 0): 0}
        # (effort, row, col)
        heap = [(0, 0, 0)]
        while heap:
            d, r, c = heappop(heap)
            if (r, c) == goal:
                return d
            if d > dist[(r, c)]:
                continue  # stale
            here = heights[r][c]
            for dr, dc in steps:
                nr, nc = r + dr, c + dc
                if not 0 <= nr < rows:
                    continue
                if not 0 <= nc < cols:
                    continue
                h = heights[nr][nc]
                step = abs(h - here)
                # effort = biggest step
                nd = max(d, step)
                # v: the neighbour cell
                v = (nr, nc)
                old = dist.get(v, INF)
                if nd >= old:
                    continue
                dist[v] = nd
                heappush(heap,
                         (nd, nr, nc))
        return 0
# O(R*C log(R*C)) time, R*C cells.

Edsger Dijkstra came up with the algorithm in 1956 in Amsterdam. In a 2001 interview (printed in Communications of the ACM) he said he was shopping with his fiancée, they sat down on a café terrace for a coffee, and he designed it there: "a twenty-minute invention", worked out without pencil and paper. He wanted a demo for a new computer, so he asked it for the shortest route between two Dutch cities. He published it in 1959.

It is still at work today. OSPF is a routing protocol used inside many company and internet-provider networks. Its standard (RFC 2328) has every router build a map of the network and run Dijkstra's algorithm on it to pick the shortest path to every other router.
  • Weighted edges? BFS finds fewest stops, not the shortest time. Use Dijkstra.
  • Heap of (distance, node) + a dist dict. Pop the closest, try each neighbour, push if it got better. Skip stale entries.
  • Only works when no edge weight is negative. Cost O(E log E).
