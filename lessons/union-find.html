Union-Find keeps track of groups that keep merging. It answers "are these two in the same group?" almost instantly, even while new connections keep arriving.

The idea

Picture a party. At first, everyone stands alone. Then people get introduced, and small friend groups form and merge. Each group picks one leader.

Want to know if Ann and Bob are in the same group? Don't walk around the whole room. Ask each of them "who is your leader?" Same leader means same group.

Two groups meet? The two leaders shake hands, and one of them becomes the leader of everyone. That is all Union-Find does. It has two moves:

  1. find(x): who is x's leader?
  2. union(a, b): merge a's group and b's group.

How it is stored. One list, parent. Each person points to someone in their group: parent[x]. A leader points to itself. To find x's leader, follow the pointers up until someone points to themselves. Each group is a small tree with the leader at the top.

Now union(2, 5). find(2) is 1. find(5) is 4. Different leaders, so we merge: point leader 4 at leader 1. Only one pointer changes.

  N3["3"] --> N1
  N4["4"] --> N1

Now find(5) goes 5 → 4 → 1. Same leader as 2, so 2 and 5 are connected.

Two small tricks keep it fast.

  • Path compression. While find walks up, it points everyone it passes straight at the leader. Next time, it's one step. In code it's one line: parent[x] = find(parent[x]).
  • Union by size. When two groups merge, put the smaller group under the bigger one. Then the trees stay short.

With both tricks, each find or union takes almost constant time. You can treat it as O(1).

In Python

class UnionFind:
    def __init__(self, n):
        # everyone is their own leader
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        p = self.parent
        if p[x] != x:
            # path compression:
            # point x at the leader
            p[x] = self.find(p[x])
        return p[x]

    def union(self, a, b):
        ra = self.find(a)
        rb = self.find(b)
        if ra == rb:
            # already together
            return False
        # union by size:
        # small group under big
        s = self.size
        if s[ra] < s[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        s[ra] += s[rb]
        # two groups merged
        return True

Cost: O(n) to set up, then each find or union is close to O(1). Memory is O(n) for the two lists.

A handy habit: union returns True only if it really merged two groups. Count the Trues, and you know how many groups are left: start with n, subtract one per merge.

When to use it instead of BFS or DFS

A BFS or DFS answers "is there a path?" too. But it walks the whole graph each time. Reach for Union-Find when:

  • Connections arrive one at a time, and after each one you ask "are these connected yet?"
  • You need the number of groups.
  • You need to spot the edge that closes a loop (both ends already have the same leader).

You don't even need to build an adjacency list. Just feed it the edges.

A province is a group. Start with n groups. For every pair i < j with isConnected[i][j] == 1, call union(i, j), and take one off the count each time it returns True. 
# paste the UnionFind class here
class Solution:
    def findCircleNum(
        self,
        isConnected: List[List[int]]
    ) -> int:
        n = len(isConnected)
        uf = UnionFind(n)
        groups = n
        for i in range(n):
            # the matrix is symmetric:
            # j > i is enough
            for j in range(i + 1, n):
                if isConnected[i][j]:
                    if uf.union(i, j):
                        groups -= 1
        return groups
# O(n^2) time to read the matrix.
Add the edges in order. The extra edge is the first one whose two ends already share a leader: that edge closes a loop. Nodes are numbered from 1, so make the Union-Find one bigger. 
# paste the UnionFind class here
class Solution:
    def findRedundantConnection(
        self, edges: List[List[int]]
    ) -> List[int]:
        # nodes are 1..n: size n + 1
        uf = UnionFind(len(edges) + 1)
        for a, b in edges:
            # False: already joined,
            # this edge makes a loop
            if not uf.union(a, b):
                return [a, b]
        return []
# O(n) unions, each close to O(1).
Stretch. Letters are the people: 26 of them, ord(ch) - ord("a") turns a letter into 0..25. First pass: union every a==b. Second pass: for every a!=b, if a and b share a leader, it's impossible. 
# paste the UnionFind class here
class Solution:
    def equationsPossible(
        self, equations: List[str]
    ) -> bool:
        uf = UnionFind(26)

        def num(ch):
            return ord(ch) - ord("a")

        # e is "a==b" or "a!=b"
        # e[0], e[3]: letters
        # e[1]: "=" or "!"
        for e in equations:
            if e[1] == "=":
                a = num(e[0])
                b = num(e[3])
                uf.union(a, b)
        for e in equations:
            if e[1] == "!":
                a = uf.find(num(e[0]))
                b = uf.find(num(e[3]))
                if a == b:
                    return False
        return True
# Two passes over the equations: O(n).

You want to connect every town with cables (or roads, or pipes), and each possible link has a price. What is the cheapest set of links that still connects everyone? This is called a minimum spanning tree.

Kruskal's algorithm (Joseph Kruskal, 1956) solves it simply: sort the links from cheapest to dearest, then take each one unless it would make a loop. "Would this link make a loop?" is exactly the Redundant Connection check above: are both towns already in the same group? Union-Find is the standard way to answer it, and textbooks such as Introduction to Algorithms teach Kruskal with it.

How fast is it really? In 1975 Robert Tarjan proved that, with both tricks, a find costs on average a tiny number of steps. That number does grow with n, but so slowly that it stays below 5 for any input that could fit in our universe.
  • parent list: follow pointers up to the leader. Same leader = same group.
  • find with parent[x] = find(parent[x]), union joins two leaders (small group under big).
  • Use it when edges arrive one by one: count groups, or spot the edge that closes a loop.
