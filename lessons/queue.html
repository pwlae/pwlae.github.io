A queue is the fair line: whoever arrived first is served first. You'll use it to handle things in the order they came in, and later it powers breadth-first search on trees and graphs.

The idea

Think of the queue at a ticket barrier. New people join at the back. The person at the front goes through next. Nobody pushes in. That's "first in, first out", the opposite of a stack (where the newest item leaves first).

flowchart TD
  J["append(2): join at the back"] --> B["2 (back)"] --> M["7"] --> F["4 (front)"] --> L["popleft() → 4 leaves first"]

Items move down the line: join at the back, leave from the front.

In Python: use deque

You could use a list with pop(0), but that's slow. Removing the first item makes every other item shift one place left, which is O(n). Use collections.deque ("deck", short for double-ended queue) instead. Adding or removing at either end is O(1).

from collections import deque

q = deque()
q.append(4)  # join at the back
q.append(7)
q.append(2)  # now deque([4, 7, 2])
q[0]         # peek at the front: 4
q.popleft()  # leave from the front: 4
len(q)       # 2, deque([7, 2]) left
if q:        # non-empty?
    ...

# Both ends work, so a deque can
# also act as a stack:
q.appendleft(9)  # deque([9, 7, 2])
q.pop()          # 2, from the back

On LeetCode, deque is already imported.

When to think "queue"

  • Things must be handled in arrival order: requests, tasks, messages.
  • You keep only recent items: drop old ones from the front while they're too old.
  • You explore level by level (nearest first). That's breadth-first search, coming in the trees and graphs lessons.

Worked example: the last 3,000 milliseconds

Count how many requests arrived in the last 3,000 ms. Each new time joins at the back. Then, while the front is older than t - 3000, drop it. What's left is exactly the recent window.

new time tdrop while front < t − 3000queue afteranswer
1nothing[1]1
100nothing[1, 100]2
3001nothing (1 ≥ 1)[1, 100, 3001]3
3002drop 1 (1 < 2)[100, 3001, 3002]3

Every time is added once and removed at most once, so the total work is O(n). It's the sliding window idea, with a queue holding the window.

Your turn

The worked example. Keep a deque in self, append t, pop old times from the left, return the length. 
class RecentCounter:
    def __init__(self):
        self.q = deque()

    def ping(self, t: int) -> int:
        self.q.append(t)
        # too old: leave from the front
        while self.q[0] < t - 3000:
            self.q.popleft()
        return len(self.q)
Use two stacks (lists): inbox for pushes, outbox for pops. When outbox is empty and you need the front, pour everything from inbox into outbox. Pouring reverses the order, so the oldest item ends up on top. 
class MyQueue:
    def __init__(self):
        self.inbox = []
        self.outbox = []

    def push(self, x: int) -> None:
        self.inbox.append(x)

    def _refill(self):
        if not self.outbox:
            # reversing: oldest on top
            while self.inbox:
                x = self.inbox.pop()
                self.outbox.append(x)

    def pop(self) -> int:
        self._refill()
        return self.outbox.pop()

    def peek(self) -> int:
        self._refill()
        return self.outbox[-1]

    def empty(self) -> bool:
        return (not self.inbox
                and not self.outbox)
# Each item is moved at most once, so
# every operation is O(1) on average.
Use one queue. After you append a new item, rotate the queue: move every older item from the front to the back. Now the newest item is at the front, ready to leave first. 
class MyStack:
    def __init__(self):
        self.q = deque()

    def push(self, x: int) -> None:
        q = self.q
        q.append(x)
        # rotate older items behind x
        for _ in range(len(q) - 1):
            q.append(q.popleft())

    def pop(self) -> int:
        return self.q.popleft()

    def top(self) -> int:
        return self.q[0]

    def empty(self) -> bool:
        return not self.q
# push is O(n), the others are O(1).

A Python list is one long row of boxes, so removing from the front means shifting everything. A deque is built differently: a chain of small blocks of 64 slots each, linked together. Adding at either end just fills the next free slot in the first or last block, or links on a new block when that one is full. Nothing ever shifts.

Job queues and message brokers that pass work between computers (such as RabbitMQ) are built around the same first-in, first-out promise.
  • Queue = first in, first out. Join at the back, leave from the front.
  • Use deque: append, popleft, q[0], all O(1). Never list.pop(0).
  • Think queue for arrival order, "only the recent ones", and (soon) level-by-level search.
