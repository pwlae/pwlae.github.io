This is the most useful trick in easy LeetCode: spend a little memory to remember what you've seen, so you never have to search for it again. In Python that means a set or a dict.

The idea

Think of a theatre cloakroom. You hand over your coat and get ticket number 37. When you come back, the attendant doesn't search through every coat. They go straight to hook 37. Finding your coat takes the same time whether there are 10 coats or 1,000.

A hash table works the same way. A hash function turns any key (a word, a number) into a hook number, and the value is stored on that hook. To look something up, Python recomputes the hook number and goes straight there.

flowchart TD
  K["key: 'apple'"] --> H["hash function"]
  H --> S["hook 3"]
  S --> V["value: 5"]

Sometimes two keys get the same hook (a collision). Python handles that for you, and on average a lookup still takes O(1).

Python gives you two hash tables:

  • set answers "have I seen this?"
  • dict answers "what do I know about this?" (where I saw it, how many times…)

In Python

seen = set()
seen.add(4)
4 in seen               # True, O(1)

where = {}              # value -> index
where[10] = 0
10 in where             # True, O(1): checks keys
where[10]               # 0
where.get(99)           # None instead of an error

Keys must be things that can't change: numbers, strings and tuples work. Lists can't be keys (use tuple(my_list) if you need to).

The big trick: one pass instead of two loops

Many problems ask "is there a pair that…?". The obvious answer checks every pair with two loops: O(n²). The hash-table answer walks the list once, and for each number asks the set or dict "have I already seen the partner I need?". That's O(n) time, paid for with O(n) memory.

seen = set()
for x in nums:
    if partner_of(x) in seen:   # O(1) lookup instead of a second loop
        ...found it...
    seen.add(x)

Your turn

Walk through the list with a set. If the number is already in the set, you found a duplicate. 
class Solution:
    def containsDuplicate(self, nums: List[int]) -> bool:
        seen = set()
        for x in nums:
            if x in seen:
                return True
            seen.add(x)
        return False
# O(n) time, O(n) space. One-liner: return len(set(nums)) != len(nums)
Exactly the worked example. A dict from number to index, and check for target - x before you store x. 
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}                    # number -> its index
        for i, x in enumerate(nums):
            need = target - x
            if need in seen:
                return [seen[need], i]
            seen[x] = i
Two words are anagrams if every letter appears the same number of times in both. Count letters in a dict for each word and compare the two dicts. 
class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        if len(s) != len(t):
            return False
        count = {}
        for ch in s:
            count[ch] = count.get(ch, 0) + 1
        for ch in t:
            count[ch] = count.get(ch, 0) - 1
            if count[ch] < 0:        # t has more of this letter than s
                return False
        return True
# O(n). Also fine: return sorted(s) == sorted(t), which is O(n log n).
Count the letters available in the magazine. Then "spend" them one by one for the note. If a count would go below zero, you can't make the note. 
class Solution:
    def canConstruct(self, ransomNote: str, magazine: str) -> bool:
        available = {}
        for ch in magazine:
            available[ch] = available.get(ch, 0) + 1
        for ch in ransomNote:
            if available.get(ch, 0) == 0:
                return False
            available[ch] -= 1
        return True

Git doesn't name your files by their path. It stores each file's content under its hash, a 40-character code like e69de29b… computed from the content itself. A commit is stored the same way.

Same content always gives the same hash, so a file that appears in a thousand commits is stored only once. And because any change, even one letter, gives a completely different hash, Git can tell instantly whether anything changed.
  • set = "have I seen it?", dict = "what do I know about it?". Both look up in O(1).
  • Turn "check every pair" (O(n²)) into one pass (O(n)): ask the set/dict for the partner, then store the current item.
  • Keys must be unchangeable: numbers, strings, tuples. Not lists.
