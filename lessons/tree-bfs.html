Breadth-first search (BFS) visits a tree one row at a time: the root, then all its children, then all the grandchildren. It's the right tool whenever a question says "per level", "nearest" or "shortest".

The idea

In the depth-first lesson you went all the way down one branch before trying the next. Breadth-first is the other way round. Think of reading a family tree generation by generation: first the grandparent, then every parent, then every child, left to right.

A level is one row of the tree. The root is level 1, its children are level 2, and so on. Here is the tree from the last lesson. BFS reads it as 4, then 2 7, then 1 3 6 9.

How do you remember who's next? With a queue: first in, first out, like the queue at a shop. Each step:

  1. Take the node at the front of the queue.
  2. Look at it (record its value, check it, whatever the problem asks).
  3. Add its children to the back of the queue.

Because children always join behind everyone already waiting, a whole level leaves the queue before the next level starts. Here is the queue for our tree, at the start of each level:

endemptydone

Notice: at the start of each level, the queue holds exactly that level. That's the key to the template below.

In Python

Use deque from the queue lesson. popleft() takes from the front, append() adds to the back.

from collections import deque

def levels(root):
    if root is None:
        return []
    out = []
    queue = deque([root])
    while queue:
        # queue holds exactly one level
        size = len(queue)
        row = []
        for _ in range(size):
            node = queue.popleft()
            row.append(node.val)
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)
        # one whole level is done
        out.append(row)
    return out

The trick is size = len(queue) before the inner loop. The children you add during the loop belong to the next level, and the loop stops before reaching them. For our tree this returns [[4], [2, 7], [1, 3, 6, 9]].

Each node goes into the queue once and out once: O(n) time. The queue holds at most one level, which can be about half the nodes: O(n) space.

BFS or DFS?

Both visit every node, so for many problems either works. Pick BFS when the question is about:

  • Levels: "the average of each row", "the rightmost node of each row".
  • Nearest or shortest: "the closest leaf to the root". BFS meets nodes in order of distance from the root, so the first match is the nearest one and you can stop early. DFS might wander down a very long branch first.

Pick DFS (recursion) when the answer for a node is built from the answers of its subtrees, like depth or "same tree".

Use the template. Instead of collecting a row, add up the values of the level and divide by size at the end of the inner loop. 
class Solution:
    def averageOfLevels(
        self, root: Optional[TreeNode]
    ) -> List[float]:
        out = []
        # q is the queue of nodes
        q = deque([root])
        while q:
            size = len(q)
            total = 0
            for _ in range(size):
                node = q.popleft()
                total += node.val
                if node.left:
                    q.append(node.left)
                if node.right:
                    q.append(node.right)
            # average of this level
            out.append(total / size)
        return out
# O(n) time, O(n) space.
Count levels as you go. The first leaf you take out of the queue (no left and no right child) is the nearest one, so return the current level right away. Don't forget the empty tree. 
class Solution:
    def minDepth(
        self, root: Optional[TreeNode]
    ) -> int:
        if root is None:
            return 0
        q = deque([root])
        depth = 0
        while q:
            depth += 1
            for _ in range(len(q)):
                node = q.popleft()
                left = node.left
                right = node.right
                # a leaf: the nearest one
                if not (left or right):
                    return depth
                if left:
                    q.append(left)
                if right:
                    q.append(right)
        return depth
# Stops early at the nearest leaf.
Cousins are on the same level but have different parents. Put (node, parent) pairs in the queue. For each level, note the parent of x and the parent of y if you see them. After the level: both found means check the parents differ; only one found means they can't be cousins. 
class Solution:
    def isCousins(
        self, root: Optional[TreeNode],
        x: int, y: int,
    ) -> bool:
        # each item: (node, its parent)
        q = deque([(root, None)])
        while q:
            px = py = None
            for _ in range(len(q)):
                node, par = q.popleft()
                if node.val == x:
                    px = par
                if node.val == y:
                    py = par
                for k in (node.left,
                          node.right):
                    if k is None:
                        continue
                    q.append((k, node))
            # both on this level?
            if px and py:
                return px is not py
            # only one: different levels
            if px or py:
                return False
        return False

Languages like Java and JavaScript free unused memory for you with a garbage collector. One classic design, published by C. J. Cheney in 1970, copies every object that is still in use into a fresh area of memory and throws the old area away.

Cheney's algorithm finds those objects breadth-first: copy the objects the program points to directly, then the objects they point to, and so on. The clever bit: the fresh memory area is the queue. One pointer marks the next copied object to look at (the front), another marks where the next copy goes (the back). When the two meet, the queue is empty and the work is done, with no extra memory for a queue at all.

The idea is still used for the "young generation": the area where new, mostly short-lived objects live. V8, the JavaScript engine in Chrome and Node.js, cleaned its young generation with Cheney's algorithm until 2017 (V8 6.2), when it switched to a parallel copying collector that spreads the same job over several threads.
