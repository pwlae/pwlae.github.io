Backtracking is a way to try every possible choice, one step at a time, and undo a step when it leads nowhere. Use it when a problem says "list all the ways": all subsets, all orders, all paths.

The idea

Picture a maze. You walk down a path. At a fork, you pick one way. If you hit a dead end, you step back to the last fork and try the next way. You keep going until you have tried every way from every fork.

%%{init: {"flowchart": {"rankSpacing": 26, "nodeSpacing": 20, "padding": 6}}}%%
flowchart TD
  S["Start"] --> F["Fork"]
  F -->|"try left"| D["Dead end"]
  D -.->|"step back"| F
  F -->|"try right"| E["Exit!"]

That "step back" is the whole trick. In code, every step has three parts:

  1. Choose: add one item to the path you are building.
  2. Explore: call the function again (recursion) to make the next choice.
  3. Un-choose: remove that item again, so the path is clean for the next option.

Example: list all subsets of [1, 2]. A subset is any group you can pick from the list, including none of it. For each number you have two choices: take it or skip it. Draw every choice and you get a decision tree:

%%{init: {"flowchart": {"rankSpacing": 30, "nodeSpacing": 10, "padding": 6}}}%%
flowchart TD
  A["[ ]"] -->|"take 1"| B["[1]"]
  A -->|"skip 1"| C["[ ]"]
  B -->|"take 2"| D["[1, 2]"]
  B -->|"skip 2"| E["[1]"]
  C -->|"take 2"| F["[2]"]
  C -->|"skip 2"| G["[ ]"]

Each leaf (a box at the bottom) is one answer. Backtracking walks this tree depth-first: down the left side, back up, then down the next branch, just like DFS on a tree.

In Python

def subsets(nums):
    result = []
    path = []

    def go(i):
        # base case: all decided
        if i == len(nums):
            # save a copy of the path
            result.append(path[:])
            return
        # option 1: take nums[i]
        path.append(nums[i]) # choose
        go(i + 1)            # explore
        path.pop()           # un-choose
        # option 2: skip nums[i]
        go(i + 1)

    go(0)
    return result

subsets([1, 2])
# [[1, 2], [1], [2], []]

Two details trip everyone up:

  • Save a copy: path[:], not path. There is only one path list, and it changes all the time. Save the list itself and every answer ends up empty.
  • Every append needs a pop. After the "take" branch finishes, the path must look exactly as it did before.

Cost. A list of n numbers has 2n subsets (each number doubles the count), and copying each one takes up to n steps: O(n · 2n). That is exponential, and it's fine here: when the problem asks for all the answers, there simply are that many. That's why these problems keep n small (often 10 or less).

Worked example

Watch path while subsets([1, 2]) runs:

SteppathSaved
take 1[1]
take 2, end[1, 2][1, 2]
pop 2, skip 2, end[1][1]
pop 1, skip 1[ ]
take 2, end[2][2]
pop 2, skip 2, end[ ][ ]

The path grows and shrinks like a stack. When the function finishes, it is empty again.

Your turn

Each problem uses the same template. Before coding, ask: what is the choice at each step, and when is the path finished?

Take or skip each number, exactly like the template. You don't need the path itself: carry the running XOR (^, see Bit tricks) as an argument, and add it to the total at each leaf. 
class Solution:
    def subsetXORSum(
        self, nums: List[int]
    ) -> int:
        def go(i, xor):
            # leaf: one subset done
            if i == len(nums):
                return xor
            # take nums[i]
            take = go(i + 1,
                      xor ^ nums[i])
            # skip nums[i]
            skip = go(i + 1, xor)
            return take + skip

        return go(0, 0)
# 2^n subsets: O(2^n) time.
Walk the tree with DFS. Choose: add the node's value to path. If it's a leaf (no children), save "->".join(path). Explore both children. Un-choose: path.pop(). 
class Solution:
    def binaryTreePaths(
        self, root: Optional[TreeNode]
    ) -> List[str]:
        result = []
        path = []

        def go(node):
            if not node:
                return
            # choose
            path.append(str(node.val))
            if not (node.left
                    or node.right):
                # leaf: save this path
                s = "->".join(path)
                result.append(s)
            else:
                # explore
                go(node.left)
                go(node.right)
            # un-choose
            path.pop()

        go(root)
        return result
The watch has 10 lights: hours worth 8, 4, 2, 1 and minutes worth 32, 16, 8, 4, 2, 1. For each light, take it (turn it on) or skip it. At the end, keep the time only if exactly turnedOn lights are on, hours < 12 and minutes < 60. 
class Solution:
    def readBinaryWatch(
        self, turnedOn: int
    ) -> List[str]:
        # (hours, minutes) per light
        leds = [(8, 0), (4, 0),
                (2, 0), (1, 0),
                (0, 32), (0, 16),
                (0, 8), (0, 4),
                (0, 2), (0, 1)]
        result = []

        def go(i, left, h, m):
            # invalid time: prune
            if h > 11 or m > 59:
                return
            # all lights on: one answer
            if left == 0:
                t = f"{h}:{m:02d}"
                result.append(t)
                return
            # ran out of lights
            if i == len(leds):
                return
            dh, dm = leds[i]
            # take light i
            go(i + 1, left - 1,
               h + dh, m + dm)
            # skip light i
            go(i + 1, left, h, m)

        go(0, turnedOn, 0, 0)
        return result
# Stopping early on a bad time is
# called pruning: skip whole branches.
Stretch. Now each step has 3 or 4 choices instead of 2: one per letter on that phone key. Loop over the letters: append, recurse to the next digit, pop. The path is finished when it has one letter per digit. Empty input? Return []. 
class Solution:
    def letterCombinations(
        self, digits: str
    ) -> List[str]:
        if not digits:
            return []
        keys = {"2": "abc", "3": "def",
                "4": "ghi", "5": "jkl",
                "6": "mno", "7": "pqrs",
                "8": "tuv", "9": "wxyz"}
        result = []
        path = []

        def go(i):
            # one letter per digit: done
            if i == len(digits):
                s = "".join(path)
                result.append(s)
                return
            for ch in keys[digits[i]]:
                # choose, explore, undo
                path.append(ch)
                go(i + 1)
                path.pop()

        go(0)
        return result
# Up to 4^n answers: O(n * 4^n).

Regular expressions ("regex") are patterns for searching text. Python's re module matches them by backtracking: its official guide says that when the rest of the pattern doesn't match, "the matching engine will then back up and try again".

Usually that is quick. But some patterns, like .*.*=.*, give the engine a huge number of ways to try before it can say "no match". On 2 July 2019, Cloudflare (a company whose network sits in front of a huge number of websites) deployed one such regex in its firewall rules. CPUs across its network jumped to nearly 100%, and for 27 minutes visitors to Cloudflare's customers' sites saw a "502" error page instead. Afterwards Cloudflare planned to switch to regex engines like re2 or Rust's regex crate, which do not backtrack, so their run time is guaranteed.
  • Template: choose (append), explore (recurse), un-choose (pop).
  • At the leaf, save a copy: path[:] or "".join(path).
  • "List all the ways" means exponentially many answers. That's expected, and n is small.
