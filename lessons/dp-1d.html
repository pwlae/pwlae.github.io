Dynamic programming (DP) is recursion that remembers the answers it has already worked out. It turns problems that take forever into one quick pass over a list.

The idea

Imagine someone asks you "what is 1 + 1 + 1 + 1 + 1?" You count: 5. Now they add "+ 1" at the end. You don't count again from the start: you remember 5 and say 6. That is DP: build big answers from small answers you saved.

You met the problem in the Recursion lesson: plain fib(n) computes the same small values again and again. Here is the same thing with a staircase. You climb 1 or 2 steps at a time. How many ways are there to reach step n?

To stand on step 4, your last move came either from step 3 (a 1-step) or from step 2 (a 2-step). So:

ways(4) = ways(3) + ways(2)

Draw the calls and you see the waste:

With a memory, ways(2) is worked out once. The second time, we just look it up. Each step is computed only once, so the cost drops from exponential to O(n).

There's an even simpler way to see it. Instead of starting at the top and going down, start at the bottom and go up. Fill a list called dp, left to right. Each box is the sum of the two boxes before it:

%%{init: {"flowchart": {"rankSpacing": 14, "nodeSpacing": 10, "padding": 6}}}%%
flowchart LR
  A["1"] --> B["1"] --> C["2"] --> D["3"] --> E["5"] --> F["8"]

Box i is dp[i]: the number of ways to reach step i. dp[5] is 8.

The 3 questions

Every DP problem in this lesson is solved by answering three questions in words before writing code:

  1. What does dp[i] mean? Stairs: "the number of ways to reach step i".
  2. How does it come from smaller answers? Stairs: dp[i] = dp[i-1] + dp[i-2], because the last move was 1 step or 2 steps.
  3. What are the first values? Stairs: dp[0] = 1 (stay where you are: one way) and dp[1] = 1.

Once the three answers are clear, the code almost writes itself.

In Python

Two ways, same idea. Top-down: write the recursion and add @cache, which saves every answer (a hash map from input to answer, built for you).

from functools import cache

@cache
def ways(i):
    # first values
    if i <= 1:
        return 1
    # last move: 1 step or 2 steps
    return ways(i - 1) + ways(i - 2)

Bottom-up: fill the list from small to big. No recursion, so no depth limit.

def ways(n):
    dp = [0] * (n + 1)
    # first values
    dp[0] = 1
    if n >= 1:
        dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

Look: dp[i] only needs the last two boxes. So keep just two numbers:

def ways(n):
    # a = dp[i-2], b = dp[i-1]
    a, b = 1, 1
    for _ in range(n - 1):
        a, b = b, a + b
    return b

Cost. All three versions do one pass over the steps: O(n) time. The first two keep n saved answers: O(n) space. The last one keeps two numbers: O(1) space.

This is the worked example. Write the two-variable version from memory: start with a, b = 1, 1 and slide forward. 
class Solution:
    def climbStairs(
        self, n: int
    ) -> int:
        # a = ways to step i-2
        # b = ways to step i-1
        a, b = 1, 1
        for _ in range(n - 1):
            a, b = b, a + b
        return b
# One pass: O(n) time, O(1) space.
Like Fibonacci, but each number is the sum of the three before it. First values: 0, 1, 1. Keep three variables and slide them forward. 
class Solution:
    def tribonacci(
        self, n: int
    ) -> int:
        # first values
        if n == 0:
            return 0
        if n <= 2:
            return 1
        # last three numbers
        a, b, c = 0, 1, 1
        for _ in range(n - 2):
            a, b, c = b, c, a+b+c
        return c
# O(n) time, O(1) space.
Question 1: dp[i] = the cheapest cost to reach step i. The top is step len(cost). Question 2: you came from step i-1 (and paid cost[i-1]) or from step i-2 (and paid cost[i-2]). Take the min. Question 3: you may start on step 0 or 1 for free. 
class Solution:
    def minCostClimbingStairs(
        self, cost: List[int]
    ) -> int:
        n = len(cost)
        # dp[i]: cheapest way to reach i
        dp = [0] * (n + 1)
        # dp[0] = dp[1] = 0: free start
        for i in range(2, n + 1):
            one = dp[i-1] + cost[i-1]
            two = dp[i-2] + cost[i-2]
            dp[i] = min(one, two)
        # the top is step n
        return dp[n]
# O(n) time. Keep only two numbers
# to get O(1) space.
Stretch. Question 1: dp[i] = the most money from the first i houses. Question 2: for house i you either skip it (keep dp[i-1]) or rob it (its money plus dp[i-2], since the house next to it is off limits). Take the max. Question 3: no houses, no money. 
class Solution:
    def rob(
        self, nums: List[int]
    ) -> int:
        # best from houses before the
        # last one, and up to the last
        prev2, prev1 = 0, 0
        for money in nums:
            rob = prev2 + money
            skip = prev1
            prev2, prev1 = (
                prev1, max(rob, skip))
        return prev1
# One pass: O(n) time, O(1) space.

TeX is the typesetting program behind LaTeX, which many scientists use to write papers. Its source code calls line breaking "probably the most interesting algorithm of TeX".

A simple program fills each line with as many words as fit, then moves on (that's greedy). Sometimes this leaves one line full of ugly wide gaps. TeX instead looks at the whole paragraph and picks the set of breaks that looks best overall. It was designed by Donald Knuth and Michael Plass, and described in their 1981 paper "Breaking Paragraphs into Lines".

It works the DP way: for each possible break point, TeX keeps the best way to lay out the text up to there, built from the best answers for earlier break points. The paper shows this is the same as finding a shortest path through a network of break points, which is also how it avoids trying every combination.

  • If dp[i] only needs the last two values, keep two variables: O(1) space.
