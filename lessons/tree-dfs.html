A binary tree is like a linked list where each node can point to two next nodes instead of one. Depth-first search walks it by going all the way down one branch before trying the next, and recursion makes that only a few lines long.

The idea

Think of a family tree drawn upside down: one person at the top, their children below, their grandchildren below that. A binary tree is the same, but every person has at most two children, a left one and a right one.

A few words you will see everywhere:

  • Node: one box in the tree. It holds a value and two links, left and right. A missing child is None.
  • Root: the node at the top. You are given only the root, just like you are given only the head of a linked list.
  • Child: a node directly below another one. Leaf: a node with no children.
  • Depth (or height) of a tree: how many nodes are on the longest path from the root down to a leaf.

Depth-first means: from a node, go down the left branch as far as it goes, come back, then go down the right branch. You finish a whole branch before you start the next one.

The trick is that every child is the root of a smaller tree (a subtree). So a tree problem splits into the same problem on the left subtree and on the right subtree. That's recursion's "smaller step". The base case is the empty tree, None.

In Python

LeetCode gives you this class (it's in a comment above your code):

class TreeNode:
    def __init__(self, val=0,
                 left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

Almost every depth-first solution has the same shape:

def solve(node):
    # 1. base case: the empty tree
    if node is None:
        return ...
    # 2. leap of faith: solve each side
    left = solve(node.left)
    right = solve(node.right)
    # 3. combine them with this node
    return ...

Each node is visited once, so it takes O(n) time for n nodes. The waiting calls take O(h) space, where h is the depth of the tree.

Pre-order, in-order, post-order. These three names only say when you look at the node itself: before both subtrees, between them, or after them.

def walk(node, out):
    if node is None:
        return
    # pre-order: node first
    out.append(node.val)
    walk(node.left, out)
    # in-order: node in the middle
    walk(node.right, out)
    # post-order: node last

Move the out.append line to one of the three spots. For the tree above you get:

Notice the in-order result is sorted. That's no accident: this tree is a binary search tree, the topic of a later lesson.

Without recursion. Recursion uses Python's call stack. You can use your own stack instead. Pre-order: pop a node, record it, push its right child, then its left child (so the left one is popped first).

def preorder(root):
    out = []
    stack = [root] if root else []
    while stack:
        node = stack.pop()
        out.append(node.val)
        # push right first,
        # so left comes out first
        if node.right:
            stack.append(node.right)
        if node.left:
            stack.append(node.left)
    return out

Handy for very deep trees, where recursion would pass Python's limit of about 1000 calls.

Worked example: maximum depth

The depth of a tree is 1 (for the root) plus the depth of its deeper subtree. The empty tree has depth 0.

def max_depth(node):
    if node is None:
        return 0
    left = max_depth(node.left)
    right = max_depth(node.right)
    return 1 + max(left, right)

Your turn

For each one, ask: what do I return for None, and how do I combine the left and right answers?

The worked example. Write it from memory: None gives 0, otherwise 1 plus the bigger of the two subtree depths. 
class Solution:
    def maxDepth(
        self, root: Optional[TreeNode]
    ) -> int:
        # empty tree has depth 0
        if root is None:
            return 0
        left = self.maxDepth(root.left)
        right = self.maxDepth(root.right)
        # this node adds one level
        return 1 + max(left, right)
# O(n) time. O(h) space for the calls.

"Invert" means mirror: every left child becomes a right child. At each node, swap left and right, then invert both subtrees. Return the root. 
class Solution:
    def invertTree(
        self, root: Optional[TreeNode]
    ) -> Optional[TreeNode]:
        if root is None:
            return None
        # swap the two children
        root.left, root.right = (
            root.right, root.left)
        # then mirror each subtree
        self.invertTree(root.left)
        self.invertTree(root.right)
        return root
Now you walk two trees at once. Base cases: both None means same; only one None, or different values, means not same. Otherwise both left subtrees and both right subtrees must match. 
class Solution:
    def isSameTree(
        self,
        p: Optional[TreeNode],
        q: Optional[TreeNode],
    ) -> bool:
        # both empty: same
        if p is None and q is None:
            return True
        # only one empty: not same
        if p is None or q is None:
            return False
        # values differ: not same
        if p.val != q.val:
            return False
        # both sides must match
        same = self.isSameTree
        return (same(p.left, q.left)
                and same(p.right, q.right))
Like Same Tree, but comparing the left subtree with the mirror of the right one. Write a helper mirror(a, b): the values match, a.left mirrors b.right, and a.right mirrors b.left. 
class Solution:
    def isSymmetric(
        self, root: Optional[TreeNode]
    ) -> bool:

        def mirror(a, b):
            if a is None and b is None:
                return True
            if a is None or b is None:
                return False
            if a.val != b.val:
                return False
            # outside pair, then inside pair
            outside = mirror(a.left, b.right)
            inside = mirror(a.right, b.left)
            return outside and inside

        return mirror(root.left, root.right)

When a browser loads a page, it turns the HTML into a tree called the DOM (Document Object Model). <html> is the root, <head> and <body> are its children, and every tag inside is a node further down.

The DOM standard defines "tree order" as a pre-order, depth-first walk: a node first, then everything inside it, from first child to last. When JavaScript calls document.querySelectorAll("a"), the links come back in exactly this order, which is the order they appear in the HTML source.
  • A tree node has val, left, right. Each child is the root of a smaller tree.
  • Pattern: None → base answer; solve left; solve right; combine. O(n) time.
  • Pre / in / post-order: look at the node before, between or after its two subtrees.
