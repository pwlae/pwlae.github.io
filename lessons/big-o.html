Big O is a short way to say how much slower your code gets when the input gets bigger. You need it to tell whether your answer will pass on LeetCode before you even press Submit.

The idea

Imagine your input grows from 1,000 items to 1,000,000. Does your code take the same time? A thousand times longer? A million times longer? Big O answers that question, and ignores small details like "this line runs twice".

Here are the five you will meet most, with everyday pictures:

  • O(1), constant. Opening locker number 42. It takes the same time with 10 lockers or 10,000.
  • O(log n), logarithmic. Finding a name in a paper phone book by opening it in the middle, then the middle of the half you need, and so on. Doubling the book adds just one more step.
  • O(n), linear. Walking down a train carriage checking every seat. Twice the seats, twice the time.
  • O(n log n). Good sorting. A bit more than linear, still fast.
  • O(n²), quadratic. Everyone at a party shakes hands with everyone else. Twice the people, four times the handshakes.

"n" just means "how big the input is", usually the length of the list or string.

How to spot it in Python

You don't need maths. Look at the shape of the code:

# O(1): jump straight to a box
nums[5]
# O(1): sets and dicts look up fast
x in some_set
# O(n): checks the boxes one by one
x in some_list

# one loop over n items: O(n)
for x in nums:
    total += x

# a loop inside a loop: O(n²)
for a in nums:
    for b in nums:
        if a + b == 10:
            count += 1

# O(n log n)
sorted(nums)

Watch out for hidden loops: x in some_list, nums.index(x), nums.count(x) and slicing nums[a:b] all walk through the list. Put one inside a for loop and you have O(n²) without seeing two loops.

Memory counts too

Big O also describes extra memory ("space"). Keeping a few variables like total or best is O(1) space. Building a new list or set as big as the input is O(n) space. Often you trade memory for speed: a set costs O(n) memory but turns O(n) lookups into O(1).

Will my answer pass?

Every LeetCode problem lists limits like 1 <= nums.length <= 10^4. Use them as a quick check before you code:

Biggest nWhat is usually fast enough
up to about 1,000O(n²) is fine
up to about 10,000O(n²) is borderline in Python. Try for better
100,000 or moreyou need O(n log n) or O(n)

So if n is small, the simple double loop is a perfectly good answer. Don't make it clever when it doesn't need to be.

Worked example

"Count how many numbers in the list are smaller than each number." The simple way compares every pair:

result = []
for a in nums:  # n times...
    smaller = 0
    for b in nums:  # ...n times each
        if b < a:
            smaller += 1
    result.append(smaller)
# n × n comparisons: O(n²) time,
# O(n) space for the result

If the list has 500 numbers, that's 250,000 comparisons: instant. With 1,000,000 numbers it's a million million: far too slow. The problem's limits tell you which world you are in.

len(str(x)) is the number of digits. Count the numbers where it is even. 
class Solution:
    def findNumbers(
        self, nums: List[int]
    ) -> int:
        count = 0
        for x in nums:
            # even number of digits
            if len(str(x)) % 2 == 0:
                count += 1
        return count
# One loop: O(n). Each number has at
# most 6 digits, so str() is O(1).
A palindrome reads the same backwards. s[::-1] reverses a string. Negative numbers can never be palindromes (the "-" is only at the front). 
class Solution:
    def isPalindrome(
        self, x: int
    ) -> bool:
        s = str(x)
        return s == s[::-1]
# O(d) time and space, where d is the
# number of digits.
# The follow-up asks for no string:
# build the reversed number with
# x % 10 (last digit) and x // 10
# (drop it). Same O(d) time, but
# O(1) space.

A Python dict is O(1) on average, but if many keys land on the same shelf it slows down to O(n). In 2003, researchers Scott Crosby and Dan Wallach showed that attackers could pick keys on purpose to make that happen. In 2011 the same trick was shown to freeze web servers in PHP, Java, Ruby and Python by sending one form full of carefully chosen field names.

Python's fix was to add a random secret to its string hashing, chosen fresh every time Python starts. It is on by default since Python 3.3, so attackers can no longer guess which keys collide.
  • Big O = how the work grows as the input grows. Common ones, fast to slow: O(1), O(log n), O(n), O(n log n), O(n²).
  • One loop is O(n), a loop inside a loop is O(n²), and in list hides a loop. in set doesn't.
  • Read the limits first: small n means the simple answer is fine.
