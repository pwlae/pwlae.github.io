How to use this guide

This guide is for people who learn on the way to work. One lesson fits one commute: about 10 minutes of reading, then a few small LeetCode problems.

The idea

You get better at algorithms by solving many easy problems quickly, not by spending three days on one hard problem. Each solved problem is a small win, and the small wins add up.

So every lesson works the same way:

  1. Read the idea. Short, plain words, one picture.
  2. See it in Python. One small piece of code you can reuse.
  3. Solve 3–6 problems on LeetCode, easiest first. Each one has a time box.

The 15-minute rule

Your commute ends whether you finished or not. If you think too long, you lose the thread by the next train. So:

  • Stuck for 15 minutes? Open the Hint.
  • Stuck 5 minutes after that? Open the Solution. Read it, close it, and type it in LeetCode yourself. This still counts. You learned the trick.
  • Tomorrow, solve that problem again from memory. It should take a few minutes.

Move to the next lesson when the easy problems feel quick, about 10 minutes each. You do not need to be perfect.

Reading on paper

Prefer paper to a screen on the morning train? Every lesson has a Print this lesson button. It gives you a clean black-and-white page: hints open, problem links written out, and solutions moved to the last page so you do not see them by accident. On a phone, choose Save as PDF in the print screen.

No signal in the tunnel

Open this page once while you have signal. After that it works offline, pictures included. You still need signal to submit on LeetCode. You can read the problem, think, and write your answer on paper until the next station with signal.

Interesting fact: Spaced repetition

Solving a problem again "tomorrow" is based on the spacing effect. Hermann Ebbinghaus measured it on himself in the 1880s: you remember much longer when you review across days instead of all at once. Flashcard apps like Anki plan your reviews around this idea.

Remember

  • One lesson per commute: read, then solve small problems.
  • 15 minutes stuck, open the hint. 5 more, read the solution and retype it.
  • Many quick wins beat one long fight.

Python toolkit for LeetCode

Read first: How to use this guide

Before any algorithm, you need a few Python tools you will use in almost every problem: lists, loops, dictionaries and sets. This lesson is the toolbox.

What a LeetCode answer looks like

LeetCode gives you a class with one method. You fill in the method and return the answer. You never read input or print output yourself.

class Solution:
    def getConcatenation(self, nums: List[int]) -> List[int]:
        return nums + nums

nums: List[int] is only a label: "nums is a list of whole numbers". -> List[int] says what you return. Python does not check these labels. They are there to help you read.

Lists: a row of boxes

A list is a row of boxes. Each box has a number called its index, starting from 0.

nums = [7, 2, 9, 4]
nums[0]        # 7, the first box
nums[-1]       # 4, the last box
len(nums)      # 4 boxes
nums[1:3]      # [2, 9], from index 1 up to (not including) 3
nums.append(5) # add a box at the end -> [7, 2, 9, 4, 5]

Loops: visit every box

Most easy problems are "walk through the list once and keep track of something".

for x in nums:                 # just the values
    print(x)

for i in range(len(nums)):     # just the indexes 0, 1, 2, ...
    print(i, nums[i])

for i, x in enumerate(nums):   # both at once (usually the nicest)
    print(i, x)

Handy built-ins

sum(nums)              # add everything up
max(nums), min(nums)   # biggest, smallest
sorted(nums)           # a new sorted list, nums stays the same
[x * 2 for x in nums]  # a new list built from nums ("list comprehension")

Dictionaries: labelled boxes

A dictionary (dict) stores key → value pairs, like a phone book. Looking up a key is instant. You do not search through everything.

age = {"ann": 31, "bob": 25}
age["ann"]               # 31
age["cat"] = 40          # add or change
"bob" in age             # True
age.get("dan", 0)        # 0 if "dan" is missing (no error)

count = {}
for word in ["a", "b", "a"]:
    count[word] = count.get(word, 0) + 1   # {"a": 2, "b": 1}

Sets: "have I seen this?"

A set keeps each value once, and checking "is it in there?" is instant.

seen = set()
seen.add(3)
3 in seen          # True
len(set([1, 1, 2]))  # 2, duplicates are dropped

Your turn

These problems only need lists and loops. Aim for 5–10 minutes each.

LeetCode1929. Concatenation of Array
Easy ~5 min☐ solved · https://leetcode.com/problems/concatenation-of-array/
Hint
Adding two lists with + puts them one after the other.
Solution
class Solution:
    def getConcatenation(self, nums: List[int]) -> List[int]:
        return nums + nums
LeetCode1480. Running Sum of 1d Array
Easy ~5 min☐ solved · https://leetcode.com/problems/running-sum-of-1d-array/
Hint
Keep a running total. For each number, add it to the total and append the total to a new list.
Solution
class Solution:
    def runningSum(self, nums: List[int]) -> List[int]:
        result = []
        total = 0
        for x in nums:
            total += x
            result.append(total)
        return result
LeetCode1470. Shuffle the Array
Easy ~10 min☐ solved · https://leetcode.com/problems/shuffle-the-array/
Hint
The x's are at indexes 0..n-1. The y's are at n..2n-1. So the pair number i is nums[i] and nums[i + n].
Solution
class Solution:
    def shuffle(self, nums: List[int], n: int) -> List[int]:
        result = []
        for i in range(n):
            result.append(nums[i])      # x_i
            result.append(nums[i + n])  # y_i
        return result
LeetCode1672. Richest Customer Wealth
Easy ~5 min☐ solved · https://leetcode.com/problems/richest-customer-wealth/
Hint
Each row is one customer. sum(row) is their wealth. You want the biggest one.
Solution
class Solution:
    def maximumWealth(self, accounts: List[List[int]]) -> int:
        return max(sum(row) for row in accounts)
LeetCode1512. Number of Good Pairs
Easy ~10 min☐ solved · https://leetcode.com/problems/number-of-good-pairs/
Hint
The list is small, so two loops are fine: for every i, check every j after it. Bonus: a dict of counts makes it one loop.
Solution
class Solution:
    def numIdenticalPairs(self, nums: List[int]) -> int:
        pairs = 0
        count = {}
        for x in nums:
            # x makes a good pair with every equal number seen before it
            pairs += count.get(x, 0)
            count[x] = count.get(x, 0) + 1
        return pairs
Interesting fact: Why append is fast

A Python list asks for a bit more memory than it needs, about 12% extra. Most append calls then just fill a spare box. Only now and then does the list move to a bigger block of memory. Java's ArrayList, C++'s std::vector and Go's slices use the same trick, so adding to the end is cheap on average in all of them.

Remember

  • Lists start at index 0. nums[-1] is the last item.
  • for i, x in enumerate(nums) gives index and value together.
  • dict for "key → value", set for "have I seen it?". Both look things up instantly.
